# C12-M13 S2 oracle 批量采集与用户复现分流

## 目标

为 C12-M13 的实现子项建立 FreeCADCmd expected、current mismatch 和最小 focused tests；同时保留 ORACLE-001 用户失败样例的可插入分支。

## 必读文件

- `../README.md`
- `../矩阵/c12m13_sweep_remainder_oracle_matrix.tsv`
- `../矩阵/c12m13_sweep_remainder_scope_matrix.tsv`
- `../矩阵/c12m13_sweep_remainder_blocker_queue.tsv`
- `../矩阵/c12m13_sweep_remainder_validation_matrix.tsv`

## 操作

1. 设计并采集 `c12m13` PartDesign Pipe multisection vertex expected：profile point、last section vertex、invalid middle vertex / wire count diagnostics。
2. 设计并采集 AdditivePipe / SubtractivePipe lifecycle expected：`AddSubShape`、`rawShape`、final `Shape`、Body Tip 和 downstream cache consumer。
3. 设计并采集 Part Sweep helper lifecycle expected 或 product-contract artifact：mutable API sequence、status、simulate、makeSolid 和 diagnostics。
4. 如果用户提供 ORACLE-001 request/result，最小化为 `c12m13/user-failing-sweep-preview-body`；否则保持 `waiting_user_repro`。
5. 对每条 oracle 运行 current recompute / focused tests，标出 `mismatch_confirmed`、`current_supported` 或 blocker。
6. 回写 oracle / scope / blocker / validation matrix，并将本步骤重命名为 `【已实现】`。

## 关闭条件

- S3/S4/S5 的每个代码 gate 都有 source-backed oracle 或明确 blocker。
- 没有 expected/current mismatch 的行不进入实现步骤。
- ORACLE-001 缺失时只保留 waiting row，不编造用户 fixture。

## 非目标

- 不直接改 C++。
- 不放宽 expected。
- 不把 mesh response 当作 parity 证据。
