# C12-M2 S6 Oracle 收集与发布闸门

## 目标

消费 S0-S5 的所有矩阵和 probe artifact，发布 C12-M2 结论。S6 决定是否存在后续 implementation package，但不在本包写代码。

## 发布规则

每个 row 只能发布为以下之一：

- `oracle_expected_ready`：source authority、stable expected、request-local/product boundary、current mismatch 同时成立。
- `current_covered`：stable expected 存在，但 current cad-core 已覆盖。
- `native_probe_blocked`：FreeCADCmd、helper、wrapper、native-hidden 或 collector 阻塞仍未解除。
- `product_boundary_rejected`：行为不适合 CAD Core request-local 产品边界。
- `retained_no_expected`：仍只有 crash、timeout、TypeError、notCollected、native-hidden 或 probe-only 历史证据。

## 执行步骤

1. 逐行复核 backend gap classification，不允许 S6 之前出现代码实现候选泄漏。
2. 对 `oracle_expected_ready` 行写清后续 implementation 包建议：family、source authority、expected artifact、current mismatch、C++ landing boundary、focused tests。
3. 对未 ready 行写清 blocker、close condition 和是否需要更窄 native probe 包。
4. 更新 C12-M2 README、总入口、方案和 `docs/CADCore12.0/README.md` 的最终结论。
5. 如果没有任何 `oracle_expected_ready`，发布 `oracle_probe_retained_gate` 或 `no_code_oracle_blocked_gate`，并明确不授权 C++。
6. 将本文件重命名为 `【已实现】` 后，确保 C12-M2 队列只剩表头。
