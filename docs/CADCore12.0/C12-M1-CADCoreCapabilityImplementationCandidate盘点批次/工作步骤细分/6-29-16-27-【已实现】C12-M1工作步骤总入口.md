## 执行顺序

1. S0 先冻结 live capability 和声明边界；不得直接按历史记忆选择实现项。
2. S1 只复核 source / current / tests / docs evidence，不采 oracle，不改 C++。
3. S2 给每个候选行确定 owner step 和 close condition。
4. S3 先处理唯一 active `remaining_gaps`：CopyOnChange。
5. S4 再处理 representative subset 与产品边界候选。
6. S5 处理 Part Workbench historical narrowed / non-parity evidence。
7. S6 只根据 S0-S5 矩阵发布下一包授权；没有 implementation row 时必须明确 no-code backlog gate。

## 状态纪律

- `remaining_gaps` 只是候选入口，不等于可实现 backend gap。
- `narrowed_gaps`、historical evidence、representative subset 和 non-goal 不能自动升级为 code gate。
- S6 的 implementation row 必须有 FreeCAD source authority、stable expected/current mismatch、request-local 边界和 focused tests。
- 如果没有满足条件的 implementation row，S6 必须保留 no-code backlog gate。
