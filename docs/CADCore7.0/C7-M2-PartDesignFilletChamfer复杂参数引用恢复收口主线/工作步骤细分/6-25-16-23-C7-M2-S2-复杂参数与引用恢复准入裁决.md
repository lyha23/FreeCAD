# C7-M2 S2 复杂参数与引用恢复准入裁决

## 目标

对 S1 的 rows 做准入裁决，决定 C7-M2 是否需要真正实现代码。S2 的输出必须是明确 route，不允许把未知项带到 S3。

## 必读

- 本包 `README.md`
- 本包 `6-25-16-20-C7-M2-PartDesignFilletChamfer复杂参数引用恢复收口方案.md`
- 本包 `矩阵/*.tsv`
- `docs/CADCore方案/细化方案/10-P7-PartDesign常用生态.md`
- S1 中记录的 FreeCAD 源码证据和 cad-core test/fixture evidence

## 裁决类型

- `already_closed_expected_backed`：现有 expected/tests/capability 已覆盖，S4 只发布口径。
- `oracle_pending_collect`：FreeCAD 行为需要 oracle 采集，当前不能实现或不能声明 supported。
- `backend_gap_requires_implementation`：已有 oracle/源码证据证明 cad-core active gap，S3 可实现。
- `publication_closure_only`：实现已闭合，只需同步 docs/capability/matrix。
- `diagnostic_non_goal`：不属于本包或当前 CAD Core 后端边界。

## 动作

1. 记录 live baseline 和队列状态。
2. 为每个 `backend_gap_classification` row 写入 route、证据和下一步。
3. 若产生 `backend_gap_requires_implementation`，写清必须修改的 cad-core 文件、fixture/test 范围和 FreeCAD 依据。
4. 若没有 backend gap，明确 S3/S4 只能 no-code publication closure。
5. 更新 `blocker_queue`，打开或关闭 `Code edit gate`。
6. 把本文件文件名和一级标题标记为 `【已实现】`，队列推进到 S3。

## 非目标

- 不做代码实现。
- 不采集 oracle，除非只补充文档说明采集路径。
- 不把 unsupported/non-goal 写入 supported capability。
