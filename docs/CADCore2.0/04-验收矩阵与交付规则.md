# 验收矩阵与交付规则

本文件定义 CAD Core 2.0 的完成标准。2.0 不以“新增了多少 TypeId”为主要指标，而以 FreeCAD 语义链路是否可重建、可诊断、可回归为指标。

## 总体验收门槛

每个 2.0 任务必须满足：

- 写明 FreeCAD 源码依据：绝对路径、类 / 函数、关键字段或短句。
- 写明 cad-core 落点：`document`、`graph`、`runtime`、`features`、`geometry`、`topo`、`adapters`。
- 有成功 fixture / oracle，或者明确 diagnostics / `known_gap`。
- 不从 fixture 输出倒推业务逻辑。
- 不在 adapter、runtime 输出层或 sketch executor 中做 fixture 特判。
- 修改 C++ 后执行相关 build / test；文档修改至少执行 `git diff --check`。

## 2.0 完成判定

CAD Core 2.0 可以冻结时，应同时满足：

- P5/P6 的 ExternalGeometry、InternalShape、stable subname 都引用同一个 MapperHistory / ElementMap 账本。
- FaceMaker / WireJoiner 的关键 ownership 能被 `NamedShape` / `ElementMap` 或 diagnostics 消费。
- 旧引用恢复统一走 resolver，成功时返回当前 subname 和写回建议，失败时返回稳定 diagnostics。
- ShapeFix / Refine / taper / transformed / DressUp history 不再各自散落。
- Link transaction 能让前端更新 `DocumentObject graph` 后稳定重算。
- Assembly solver 有明确接口、基础成功路径和失败 diagnostics。
- CLI / C ABI / Web adapter 复用同一 core recompute，不承载额外业务语义。
- 全部 remaining gaps 以 capabilities、diagnostics 或 known-gap expected 显式暴露。
- expected fixture 若几何仍可验收但必须暴露结构化 warning / diagnostic，应在 expected JSON 中写 `diagnostic_codes`；只有不可验收场景才使用 `known_gap` 跳过。

- `python3 -m unittest tests.test_expected_fixtures`：OK、skipped=9。
