# C6-M2 S1 失败清单与 owner 分类矩阵

## 目标

消费 S0 冻结的 failure list，为每个 mismatch 建立独立 row，明确 owner、涉及文件、初始处理动作和下游步骤。S1 的交付物是矩阵，不做代码修复。

## 必读输入

- S0 已实现文档
- `矩阵/c6m2_expected_fixture_regression_fixture_oracle_matrix.tsv`
- `矩阵/c6m2_expected_fixture_regression_scope_review_matrix.tsv`
- `矩阵/c6m2_expected_fixture_regression_backend_gap_classification.tsv`
- `cad-core/tests/test_expected_fixtures.py`

## owner 分类

| owner | 适用场景 |
| --- | --- |
| `bbox_geometry_or_occt_drift` | bbox、volume、topology 或 OCCT 版本相关差异。 |
| `diagnostic_codes_contract_drift` | diagnostic code 增删或错误合同变化。 |
| `external_geometry_count_contract_drift` | external geometry count 与 schema / executor 输出不一致。 |
| `link_schema_or_type_drift` | link 类型、PropertyLinkSub、stable subname 或 document parser 字段漂移。 |
| `assembly_solver_adapter_schema_drift` | assembly solver adapter 输出字段变化。 |
| `expected_stale_after_intended_behavior` | 当前实现是已批准行为，expected 未同步。 |
| `implementation_regression` | 当前实现偏离 FreeCAD / CAD Core 合同，应修代码。 |

## 实施内容

1. 为 S0 每个 failure 建 `C6M2-ORC-*` 行，记录 fixture、字段路径、expected/current 摘要、owner、下游步骤。
2. 将同类 failure 汇总到 `scope_review_matrix.tsv` 和 `backend_gap_classification.tsv`。
3. 为需要行动的 owner 建 `C6M2-BLK-*` 行，并写 close condition。
4. 明确哪些行进入 S2 authority，哪些可直接进入 S3/S4。
5. 完成后将本文件改名为 `6-23-22-37-【已实现】C6-M2-S1-失败清单与owner分类矩阵.md`。

## 非目标

- 不刷新 expected。
- 不修 C++。
- 不新增新 fixture。
- 不把类别总数当作完整 failure list；每个 failure 必须有 row。
