# C6-M9 S2 准入路由与产品合同裁决

## 目标

把 S1 的 Groove UpTo candidates 路由成可执行状态。S2 是 C6-M9 的关键裁决点：不能让 `partdesign_groove_upto_brepfeat_cut_native_failure` 长期作为 active gap，但也不能凭 cad-core 可构造就伪装成 FreeCAD expected-backed parity。

## 路由词典

| route | 含义 | 后续 |
| --- | --- | --- |
| `backend_gap_requires_implementation` | CAD Core 应支持且当前实现失败。 | S3 code + fixtures + tests |
| `cad_core_product_contract_non_parity` | CAD Core stateless 产品合同成立，但不是 FreeCAD native expected。 | S3 product fixtures + capability |
| `historical_native_failure` | FreeCAD native failure 是当前稳定证据，应保留 delete condition。 | S3/S4 narrowed evidence |
| `retained_exact_blocker` | 仍缺少足够证据裁成实现或 non-parity，只能保留 precise blocker。 | S4 capability/docs guard |
| `non_goal_frozen` | GUI/session/full parity 等不属于本包。 | non-goal registry |

## 动作

1. 对 `Groove Type=UpToFirst` 和 `Groove Type=UpToFace` 分别裁决 route，但两者必须作为同一语义批次收口。
2. 如果进入实现，写清最小实现范围：`feature_revolved.cpp` / `topo_shape_expansion.cpp`、fixtures/product metadata、focused tests、capability/docs。
3. 如果不进入实现，写清 native failure 或 retained blocker 的 delete/reopen condition，不得只保留模糊 active gap。
4. 更新 backend classification、blocker queue、oracle fixture、non-goal registry 和 validation matrix。

## 通过条件

- UpToFirst 与 UpToFace 都有唯一 route，且不会拆成长期单 fixture 推进。
- 如果存在实现型 route，S3 范围必须包含 code、fixtures、focused tests、capability 和 docs。
- 如果保留 native failure / exact blocker，必须写清 delete/reopen condition 和 adapter assertion 口径。
- S2 文件名和标题标记为 `【已实现】` 后，队列推进到 S3。
