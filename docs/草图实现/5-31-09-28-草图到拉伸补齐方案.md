# 草图到拉伸补齐方案

## 目标

补齐从草图提交到 Pad / Extrude 拉伸的完整链路：

1. 前端提交 `Sketcher::SketchObject` 后，后端返回可显示、可拾取的 `mesh + subshapes`。
2. 前端从 `subshapes` 选择 `InternalFaceN`，写回后续 Pad / Extrude 的 `Profile.SubList`；只有响应里的 `stableSubname` 非空时才写 `Profile.StableSubList`。
3. 后端按 `Profile.SubList=["InternalFaceN"]` 从 sketch `InternalShape` 中取面域作为拉伸输入。
4. 后续补齐复杂草图区域划分、跨重建稳定引用、完整 FreeCAD Sketcher / PartDesign 语义。

本方案只定义后续实现路线和验收边界；不把 `profiles[]`、mesh 或临时几何缓存作为前端持久模型。已批准的唯一 BREP 例外是 `ReferenceShadow.brep`，它只保存被引用单个旧 subshape 的 snapshot，用于引用恢复。

## 剩余缺口

### 1. 前端提交与写回链路

后端已经能返回 `InternalFaceN`，但完整产品链路还需要前端实现：

- 草图提交后请求 `/cad/recompute`，target 至少包含 Sketch。
- 用 `results[].subshapes` 更新拾取缓存，不新增 `profiles[]`。
- Pad 命令过滤 `object.TypeId == "Sketcher::SketchObject"` 且 `subshape.kind == "Face"` 的项。
- 把 `subshape.subname` 写入 `Profile.SubList`，把 `subshape.stableSubname` 写入 `Profile.StableSubList`。
- 创建或更新 Pad / Extrude 对象后，再以 Pad / Extrude 为 target recompute。

### 2. 完整 Sketch 内部面算法

当前内部面生成还不是完整 FreeCAD `buildInternals()` 语义。需要继续迁移：

- `FaceMakerBuildFace` 的交点分割、自相交分割和平面判定。当前已覆盖简单线框自交和
  degree=1 BSpline 自交；更高阶曲线自交仍需继续迁移。
- `WireJoiner` 的 open wire / result wire / split edge / merge edge 账本。
- 多闭合区域、孔洞、嵌套面域、相交边、自交边、样条和椭圆弧组合。当前已覆盖
  overlapping rectangles 这类 closed profile inter-edge intersection 子集，复杂曲线网络仍未完成。
- splitter 失败时的 FreeCAD 等价降级，而不是输出侧补面或按 fixture 特判。

实现落点应在 `geometry/face_maker.*`、后续正式 `WireJoiner` / FaceMaker 适配层和 `topo/` history 结构中；`sketch_object.cpp` 只保留调用顺序和属性语义。

已确认的一个实现边界：FreeCAD `SketchObject::buildInternals()` 在 `FaceMakerBuildFace` 后会调用
`WireJoiner::getOpenWires()` 并把 face 结果与 open wires 组合；因此 dangling open line 不应让已
成功生成的 bounded face 变空。当前 `cad-core` 已按这个边界保留 bounded face，并把未被 bounded
region 消费的 open wire 暴露为内部 edge / vertex；但这仍不是完整 `WireJoinerP::EdgeInfo`
ownership 账本；当前已用 bounded face 边界作为 edge fragment ownership 证据，shared edge、
tight-bound 竞争、split fragment history 仍应由正式 WireJoiner 迁移解决。
因此后续 open-wire / result-wire / split ownership 的实现继续落到 `geometry/wire_joiner.*`，
不要回到 `sketch_object.cpp` 里做输出侧修剪。
### 3. InternalFace 跨重建稳定引用

当前 `InternalFaceN` 主要是本次 recompute 内的可拾取名。要支持草图编辑后的稳定引用，需要补：

- sketch `internalShape` 的 `NamedShape`。
- `InternalFace` / `InternalEdge` / `InternalVertex` 到 `ElementMap` 的写入。
- FaceMaker / WireJoiner split history 到 `MapperHistory` / `ElementMap` 的传播。
- `elementReferenceUpdates` 对 `Profile.SubList` / `StableSubList` 的修正建议。

原则：不要用几何顺序、fixture 名、source edge 猜测来替代 history。

当前阶段的 `InternalFaceN` 还没有完整 Sketch `NamedShape` / `ElementMap`，响应中的
`stableSubname` 保持为空字符串，前端不得把当前 `InternalFaceN` 当稳定名写入
`StableSubList`。`InternalEdgeN` / `InternalVertexN` 已按 FreeCAD `getInternalElementMap()`
的范围导出可映射的原始 `EdgeN` / `VertexN` 稳定名，并可在请求侧把旧 `InternalEdgeN` /
`InternalVertexN` 当前名反解为当前内部元素；其中内部 Edge 映射已补端点 + 几何检查，避免
同端点不同曲线类型错写稳定名。后端已通过显式 `StableSubList` 标记区分
“缺省 SubList 当前名”和“调用方确实写入 StableSubList”：若 `Profile.StableSubList` 显式引用
`InternalFaceN`，当前返回 `unsupported_stable_subname`，避免把 request-local 面名持久化为稳定引用。

### 3.1 ReferenceShadow 旧几何快照恢复

`ReferenceShadow` 不是 FreeCAD 原样字段，而是把 FreeCAD 的 `ShadowSub + ElementCache`
运行期机制改造成无状态前后端可传递的引用恢复证据。详细方案单独维护在
`docs/草图实现/5-31-10-01-ReferenceShadow旧几何快照恢复方案.md`。

当前已完成第一段恢复证据通道：`cad-core/src/document/model.cpp` 能解析并保存
`ShadowSub` 与 `ReferenceShadow`，并校验它们与 `SubList` 的长度对齐、`ReferenceShadow`
基础字段、`shapeType`、`fingerprint` 对象类型和单子元素 BREP snapshot 元数据格式；
`cad_core_ffi` capabilities 已声明 `ShadowSub` / `ReferenceShadow`。`topo/reference_matcher`
已能对当前子元素计算轻量 fingerprint，并由 runtime 在 feature 执行前比较
`ReferenceShadow.fingerprint`；明显漂移时返回 `subname_semantic_drift`，不静默执行 Pad。
fingerprint 校验通过时，runtime 会在 `elementReferenceUpdates` 中返回同形 LinkSub 写回建议，
携带当前子元素 fingerprint；`PropertyLinkSubList.SubSet[]` 也按同形 `SubSet` 返回更新后的
`ReferenceShadow`。如果当前 `SubList` 指向的子元素已经不存在，`topo/reference_matcher`
会用 fingerprint 在当前目标 shape / `InternalShape` 中寻找唯一候选；唯一命中时可继续执行并
建议把 `SubList` 改写为当前名。fingerprint 多候选时返回 `subname_resolve_ambiguous`，
无候选时返回 `subname_resolve_failed`。`brep-text` 旧单子元素 snapshot 已接入恢复路径：
当 fingerprint 本身匹配多个候选，或当前 `SubList` 仍能解析但已和旧 fingerprint 漂移时，可解码旧
face BREP 并用其完整几何 fingerprint 恢复唯一 `InternalFaceN`。如果旧 face 被当前多个 face
覆盖，返回 `subname_split_requires_reselect` 要求用户重选；如果旧 face 与当前候选完全无重叠，
返回 `subname_deleted`。线段 Edge snapshot 也已按同一原则区分 split / deleted；Vertex snapshot
无当前点匹配时返回 deleted。非线 Edge snapshot 已补一个严格子集：当前多段同曲线类型 edge
采样点仍覆盖旧 edge 几何时返回 split，完全无覆盖时返回 deleted；P5 已约束圆弧和二次
BSpline。`elementReferenceUpdates` 已在成功校验或恢复后刷新当前子形状的 `brep-text`
snapshot，避免只更新 fingerprint 却继续回写旧 BREP。完整 FreeCAD
`findSubShapesWithSharedVertex()` 等价 matcher、更多曲线组合，以及完整稳定名 ElementMap
恢复仍是后续切片。

- `Profile.SubList` 非 `InternalFaceN`、找不到 subshape、`StableSubList` 长度不一致、`FullSubList` 出现时的诊断必须稳定。当前
  Pad / Pocket 已覆盖缺少 `SubList`、缺失 `InternalFaceN`、非法 `InternalEdgeN`、显式
  `StableSubList=["InternalFaceN"]`、`StableSubList` 长度不一致、`FullSubList` 输入拒绝和
  malformed `ReferenceShadow` 输入拒绝。
- Pad / Pocket 的 Two sides、Symmetric、UpToFace、UpToShape、taper 等已有 FeatureExtrude 语义要继续复用，不在 sketch executor 中分叉。

### 5. Sketch solver 边界

当前链路默认前端提交的 `Geometry` 已经是可用于建模的几何结果。若后续要求后端根据约束完整求解草图，需要单独规划 FreeCAD Sketcher solver 迁移；这不应混入 profile mesh 或 Pad profile 选择任务。

### 6. 诊断与 UX

当前 open sketch 作为 target 可以返回 `mesh: null`。如果产品要求“提交态必须有 profile”，应在前端命令层或后端 feature validator 中升级为业务诊断。建议补齐：

- open sketch 仅提交显示：`mesh: null`，无硬错误。
- Pad 使用 open / empty sketch：`execution_failed` 或更明确的 profile diagnostic。
- unsupported region：`unsupported_profile_region`。
- 多面域未选择：要求 `Profile.SubList` 明确选择一个 `InternalFaceN`。

## 实现纪律

- 不从 fixture 输出倒推业务逻辑。
- 不在 `sketch_object.cpp` 中按几何类型、fixture 名称或 split 顺序做补丁。
- 不新增 `profiles[]`。
- 不接受 `FullSubList`。
- `StableSubList` 是正式字段，不是旧 payload 兼容；但只在响应提供非空 `stableSubname` 时写入。
- 面域、open wire、split history、stable subname 的通用能力应落在 `geometry/` 与 `topo/`，executor 只串联 FreeCAD 业务调用顺序。
