# 草图到拉伸补齐方案

## 目标

补齐从草图提交到 Pad / Extrude 拉伸的完整链路：

1. 前端提交 `Sketcher::SketchObject` 后，后端返回可显示、可拾取的 `mesh + subshapes`。
2. 前端从 `subshapes` 选择 `InternalFaceN`，写回后续 Pad / Extrude 的 `Profile.SubList`；只有响应里的 `stableSubname` 非空时才写 `Profile.StableSubList`。
3. 后端按 `Profile.SubList=["InternalFaceN"]` 从 sketch `InternalShape` 中取面域作为拉伸输入。
4. 后续补齐复杂草图区域划分、跨重建稳定引用、完整 FreeCAD Sketcher / PartDesign 语义。

本方案只定义后续实现路线和验收边界；不把 `profiles[]`、mesh 或临时几何缓存作为前端持久模型。已批准的唯一 BREP 例外是 `ReferenceShadow.brep`，它只保存被引用单个旧 subshape 的 snapshot，用于引用恢复。

  degree=1 BSpline 自交、单 edge cubic BSpline 自交，以及相交 quadratic BSpline 闭合

- 多闭合区域、孔洞、嵌套面域、相交边、自交边、样条和椭圆弧组合。当前已覆盖
  overlapping rectangles / circles / arc-lens / line-arc / BSpline overlap-empty 这类 closed

已确认的一个实现边界：FreeCAD `SketchObject::buildInternals()` 在 `FaceMakerBuildFace` 后会调用

成功生成的 bounded face 变空。当前 `cad-core` 已按这个边界保留 bounded face，并把未被 bounded

ownership 账本；当前已用 bounded face 边界作为 edge fragment ownership 证据，并补了连接
leftover fragment 的 result-wire 合并子集。shared edge、tight-bound 竞争、split fragment
history 仍应由正式 WireJoiner 迁移解决。
split+separate-dangling 已精确对齐 FreeCAD 2 faces / 7 edges / 6 vertices；touching

接到已选 split edge 的 open-edge 连通分量交给 BuilderFace，T-junction endpoint 只负责切开
生成边界，不把面内 branch 自身保留成 open wire。
through-open-cutter、branch-open-cutter、cross-pattern、overlap-rectangles、overlap-circles、

three-overlap-circles 的即时 FreeCADCmd oracle 是 7 / 30 / 18，cad-core 当前已对齐。

### 3. InternalFace 跨重建稳定引用

WireJoiner history 支撑的完整 `ElementMap`，响应中的 `stableSubname` 保持为空字符串，

同端点不同曲线类型错写稳定名。后端已通过显式 `StableSubList` 标记区分

### 3.1 ReferenceShadow 旧几何快照恢复

`ReferenceShadow` 不是 FreeCAD 原样字段，而是把 FreeCAD 的 `ShadowSub + ElementCache`
运行期机制改造成无状态前后端可传递的引用恢复证据。详细方案单独维护在
`docs/草图实现/5-31-10-01-ReferenceShadow旧几何快照恢复方案.md`。

当前已完成第一段恢复证据通道：`cad-core/src/document/model.cpp` 能解析并保存
`ShadowSub` 与 `ReferenceShadow`，并校验它们与 `SubList` 的长度对齐；唯一例外是当前
`SubList` 缺失或为空的恢复请求，必须同时提供同长度的 `StableSubList + ShadowSub + ReferenceShadow`。
`ReferenceShadow` 基础字段、`shapeType`、`fingerprint` 对象类型和单子元素 BREP snapshot 元数据格式；
`cad_core_ffi` capabilities 已声明 `ShadowSub` / `ReferenceShadow`。`topo/reference_matcher`
已能对当前子元素计算轻量 fingerprint，并由 runtime 在 feature 执行前比较
`ReferenceShadow.fingerprint`；明显漂移时返回 `subname_semantic_drift`，不静默执行 Pad。
fingerprint 校验通过时，runtime 会在 `elementReferenceUpdates` 中返回同形 LinkSub 写回建议，
携带当前子元素 fingerprint；`PropertyLinkSubList.SubSet[]` 也按同形 `SubSet` 返回更新后的
`ReferenceShadow`。如果 `ShadowSub.newName` 命中 `ReferenceShadow.stableSubname`，且
`ShadowSub.oldName` 指向的当前 `Internal*` 通过旧 fingerprint / BREP 校验，runtime、Pad
executor 和 Sketch `ExternalGeometry` 会优先使用该内部元素并返回新的 `SubList` /
`StableSubList` / `ShadowSub` / `ReferenceShadow`；这对齐 FreeCAD 先试 `ShadowSub`、再查旧几何 cache 的解析顺序。如果当前
`SubList` 指向的子元素已经不存在，`topo/reference_matcher`
会用 fingerprint 在当前目标 shape / `InternalShape` 中寻找唯一候选；唯一命中时可继续执行并
建议把 `SubList` 改写为当前名。fingerprint 多候选时返回 `subname_resolve_ambiguous`，
无候选时返回 `subname_resolve_failed`。`brep-text` 旧单子元素 snapshot 已接入恢复路径：
当 fingerprint 本身匹配多个候选，或当前 `SubList` 仍能解析但已和旧 fingerprint 漂移时，可解码旧
face BREP 并用其完整几何 fingerprint 恢复唯一 `InternalFaceN`。如果旧 face 被当前多个 face
覆盖，返回 `subname_split_requires_reselect` 要求用户重选；如果旧 face 与当前候选完全无重叠，
返回 `subname_deleted`。线段 Edge snapshot 也已按同一原则区分 split / deleted；Vertex snapshot
无当前点匹配时返回 deleted。非线 Edge snapshot 已补一个严格子集：当前多段同曲线类型 edge
采样点仍覆盖旧 edge 几何时返回 split，完全无覆盖时返回 deleted；P5 已约束圆弧和二次
BSpline。`elementReferenceUpdates` 已在成功校验或恢复后刷新当前子形状的 `brep-text`
snapshot，并写回真实 `sha256`，避免只更新 fingerprint 却继续回写旧 BREP。BREP 旧几何恢复
已切到 FreeCAD-like `findSubShapesWithSharedVertex()` 的 Vertex / Edge / Face 支持类型子集：
先比共享顶点，再比边 / 面几何，避免只靠 bbox / centroid / length fingerprint 把交叉线段误判为同一引用。
更多曲线组合和完整稳定名 ElementMap 恢复仍是后续切片。`brep-bin-zstd-base64` 已接入 runtime 解码，
作为压缩传输格式参与旧几何恢复；无效 base64 / zstd / digest 仍返回引用诊断，不退回 fingerprint 伪装恢复。
