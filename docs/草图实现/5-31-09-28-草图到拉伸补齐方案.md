# 草图到拉伸补齐方案

## 目标

补齐从草图提交到 Pad / Extrude 拉伸的完整链路：

1. 前端提交 `Sketcher::SketchObject` 后，后端返回可显示、可拾取的 `mesh + subshapes`。
2. 前端从 `subshapes` 选择 `InternalFaceN`，写回后续 Pad / Extrude 的 `Profile.SubList` 与 `Profile.StableSubList`。
3. 后端按 `Profile.SubList=["InternalFaceN"]` 从 sketch `InternalShape` 中取面域作为拉伸输入。
4. 后续补齐复杂草图区域划分、跨重建稳定引用、完整 FreeCAD Sketcher / PartDesign 语义。

本方案只定义后续实现路线和验收边界；不把 `profiles[]`、mesh 或临时几何缓存作为前端持久模型。已批准的唯一 BREP 例外是 `ReferenceShadow.brep`，它只保存被引用单个旧 subshape 的 snapshot，用于引用恢复。

## 当前基线

当前 `cad-core` 已具备的能力：

- `cad-core/src/features/sketch_object.cpp::executeSketchObject()` 能为闭合草图生成 `internalShape`，并把它以 `InternalFaceN` 前缀写入 `context.mesh`。
- `cad-core/src/geometry/shape_exporter.cpp::meshForShape()` 支持 face id 前缀，Sketch 使用 `InternalFace`，其他对象仍使用默认 `Face`。
- `cad-core/src/geometry/face_maker.cpp::makeFacesFromClosedWiresAndSplitEdges()` 已覆盖简单多面域，例如矩形加贯穿分割线。
- `cad-core/src/features/feature_extrude.cpp::resolveSketchInternalFaceProfile()` 已支持 Pad / Pocket 从 `Profile.SubList=["InternalFaceN"]` 选择 sketch 内部面。
- `cad-core/src/document/model.cpp` 的 LinkSub 输入为 `value + SubList`，可选 `StableSubList`；`FullSubList` 不是正式接口，必须拒绝。
- `docs/接口规定/01-cad-recompute全量输入输出接口.md` 已约定：选择项当前名写入 `SubList`，稳定名写入 `StableSubList`，不传 `FullSubList`。

## FreeCAD 依据

后续实现应以这些 FreeCAD 源文件为语义入口：

- `src/Mod/Sketcher/App/SketchObject.h::buildInternals()`：Sketch 内部面 / 内部边的业务入口。
- `src/Mod/Sketcher/App/SketchObject.h::getElementTypes()`：Sketch 暴露 `InternalFace` / `InternalEdge` / `InternalVertex` 的元素类型依据。
- `src/Mod/Part/App/FaceMakerBuildFace.cpp`：边分割、自相交处理、`BOPAlgo_BuilderFace` 面域生成。
- `src/Mod/Part/App/FaceMaker.cpp::postBuild()`：FaceMaker 后处理和 history 传播入口。
- `src/Mod/Part/App/WireJoiner.cpp`：open wires、result wires、split / merge / history 账本。
- `src/Mod/PartDesign/App/FeatureSketchBased.h::ProfileBased`：`Profile` 是 `App::PropertyLinkSub`。
- `src/Mod/PartDesign/App/FeatureExtrude.cpp::FeatureExtrude::buildExtrusion()`：Pad / Pocket 共用拉伸主流程。
- `src/Mod/PartDesign/App/FeaturePad.cpp::Pad::execute()`：Pad 调用 `buildExtrusion(ExtrudeOption::MakeFace | ExtrudeOption::MakeFuse)`。
- `src/Mod/PartDesign/App/FeaturePocket.cpp::Pocket::execute()`：Pocket 的反向 / subtract 拉伸语义入口。

## 剩余缺口

### 1. 前端提交与写回链路

后端已经能返回 `InternalFaceN`，但完整产品链路还需要前端实现：

- 草图提交后请求 `/cad/recompute`，target 至少包含 Sketch。
- 用 `results[].subshapes` 更新拾取缓存，不新增 `profiles[]`。
- Pad 命令过滤 `object.TypeId == "Sketcher::SketchObject"` 且 `subshape.kind == "Face"` 的项。
- 把 `subshape.subname` 写入 `Profile.SubList`，把 `subshape.stableSubname` 写入 `Profile.StableSubList`。
- 创建或更新 Pad / Extrude 对象后，再以 Pad / Extrude 为 target recompute。

### 2. 完整 Sketch 内部面算法

当前内部面生成还不是完整 FreeCAD `buildInternals()` 语义。需要继续迁移：

- `FaceMakerBuildFace` 的交点分割、自相交分割和平面判定。
- `WireJoiner` 的 open wire / result wire / split edge / merge edge 账本。
- 多闭合区域、孔洞、嵌套面域、相交边、自交边、样条和椭圆弧组合。
- splitter 失败时的 FreeCAD 等价降级，而不是输出侧补面或按 fixture 特判。

实现落点应在 `geometry/face_maker.*`、后续正式 `WireJoiner` / FaceMaker 适配层和 `topo/` history 结构中；`sketch_object.cpp` 只保留调用顺序和属性语义。

### 3. InternalFace 跨重建稳定引用

当前 `InternalFaceN` 主要是本次 recompute 内的可拾取名。要支持草图编辑后的稳定引用，需要补：

- sketch `internalShape` 的 `NamedShape`。
- `InternalFace` / `InternalEdge` / `InternalVertex` 到 `ElementMap` 的写入。
- FaceMaker / WireJoiner split history 到 `MapperHistory` / `ElementMap` 的传播。
- `elementReferenceUpdates` 对 `Profile.SubList` / `StableSubList` 的修正建议。

原则：不要用几何顺序、fixture 名、source edge 猜测来替代 history。

### 3.1 ReferenceShadow 旧几何快照恢复

`ReferenceShadow` 不是 FreeCAD 原样字段，而是把 FreeCAD 的 `ShadowSub + ElementCache`
运行期机制改造成无状态前后端可传递的引用恢复证据。详细方案单独维护在
`docs/草图实现/5-31-10-01-ReferenceShadow旧几何快照恢复方案.md`。

### 4. Pad / Extrude Profile 完整性

当前重点覆盖 PartDesign Pad / Pocket 对 sketch `InternalFaceN` 的选择。后续还要明确：

- 通用 Extrude 是否允许 edge / wire / face 混合输入。
- 多面域 sketch 在 `SubList` 为空时必须继续 diagnostic，不能默认选第一个。
- `Profile.SubList` 非 `InternalFaceN`、找不到 subshape、`StableSubList` 长度不一致、`FullSubList` 出现时的诊断必须稳定。
- Pad / Pocket 的 Two sides、Symmetric、UpToFace、UpToShape、taper 等已有 FeatureExtrude 语义要继续复用，不在 sketch executor 中分叉。

### 5. Sketch solver 边界

当前链路默认前端提交的 `Geometry` 已经是可用于建模的几何结果。若后续要求后端根据约束完整求解草图，需要单独规划 FreeCAD Sketcher solver 迁移；这不应混入 profile mesh 或 Pad profile 选择任务。

### 6. 诊断与 UX

当前 open sketch 作为 target 可以返回 `mesh: null`。如果产品要求“提交态必须有 profile”，应在前端命令层或后端 feature validator 中升级为业务诊断。建议补齐：

- open sketch 仅提交显示：`mesh: null`，无硬错误。
- Pad 使用 open / empty sketch：`execution_failed` 或更明确的 profile diagnostic。
- unsupported region：`unsupported_profile_region`。
- 多面域未选择：要求 `Profile.SubList` 明确选择一个 `InternalFaceN`。

## 分阶段实施

### 阶段一：接口与前端写回闭环

目标：闭合草图提交、选面、创建 Pad、拉伸成功。

任务：

- 前端按 `subshapes` 做 face 选择，不新增 `profiles[]`。
- Pad / Extrude 写入 `Profile.value`、`Profile.SubList`、`Profile.StableSubList`。
- 后端 capability 与接口文档保持一致：声明 `StableSubList`，拒绝 `FullSubList`。
- 增加端到端用例：矩形 sketch -> 选 `InternalFace1` -> Pad -> 返回 solid mesh。

验收：

- Sketch target 返回 `Sketch:InternalFace1` mesh face id。
- Pad target 返回 solid。
- 阶段一请求 payload 不包含 `profiles[]`、BREP、`FullSubList`；后续只有 `ReferenceShadow.brep` 可以作为旧 subshape snapshot 进入 Link 属性。

### 阶段二：FreeCAD-like 内部面引擎

目标：替换当前简化面域生成，向 FreeCAD `FaceMakerBuildFace + WireJoiner` 靠齐。

任务：

- 在 `geometry/` 中补正式 FaceMaker / WireJoiner 运行态，不在 executor 中堆规则。
- 建立 edge split、wire join、open wire、result wire 的中间账本。
- 对 unsupported case 返回明确 diagnostic，不生成假面。

验收 fixture：

- 矩形 + 贯穿分割线。
- 外轮廓 + 内孔。
- inter-edge intersection。
- self-intersection。
- open wire 与 bounded faces 同时存在。
- 圆弧、椭圆弧、BSpline 参与闭合或分割。

### 阶段三：InternalShape topo naming

目标：让 `InternalFaceN` 能跨草图编辑稳定恢复。

任务：

- 为 Sketch `internalShape` 生成 `NamedShape`。
- 把 FaceMaker / WireJoiner history 接入 `ElementMap`。
- 让 `StableSubList` 指向旧稳定名时，可以解析到当前 `InternalFaceN`，或给出 split / deleted diagnostic。
- 对需要更新的引用生成 `elementReferenceUpdates`。
- 按 `docs/草图实现/5-31-10-01-ReferenceShadow旧几何快照恢复方案.md` 接入
  `ReferenceShadow`：先实现 fingerprint 校验，后续再考虑旧子元素 BREP snapshot 恢复。
- 对恢复结果在 `elementReferenceUpdates` 中携带更新后的 `ReferenceShadow`，让前端更新下一次请求的引用恢复证据。

验收：

- 插入一条不影响目标面域的草图边后，Pad 仍能恢复到同一稳定面。
- 目标面域被 split 时，返回 split diagnostic，不静默选第一个。
- 目标面域删除时，返回 deleted diagnostic。
- 稳定名仍可解析但 fingerprint 不匹配时，返回 drift / ambiguous 诊断或唯一恢复结果，不静默使用漂移 subname。

### 阶段四：ProfileBased / Extrude 扩展

目标：把 Pad / Pocket 的 sketch profile 选择推广到完整 ProfileBased 能力。

任务：

- 明确 PartDesign Pad/Pocket 与通用 Extrude 的输入差异。
- 支持更多 profile 输入形态，但保持 feature validator 拒绝非法组合。
- 复用 `FeatureExtrude::buildExtrusion()` 已有 Length、Two sides、Symmetric、UpToFace、UpToShape、taper 语义。

验收：

- 单面域、明确多面域、缺失面域、非法 subshape 都有稳定 diagnostic。
- Pad / Pocket 现有 fixture 不回退。
- 新增通用 Extrude fixture 前，先写清楚与 PartDesign Pad 的差异。

### 阶段五：Sketch solver 决策

目标：决定是否迁移完整 Sketcher solver。

任务：

- 如果前端负责求解约束，后端只验证和建模，不迁移 solver。
- 如果后端需要求解约束，单独规划 `src/Mod/Sketcher/App` solver-facing 状态、约束系统和求解流程。

验收：

- 明确接口中 `Geometry` 是已求解结果还是约束输入。
- 不把 solver 缺口误归到 profile mesh 或 Pad executor。

## 实现纪律

- 不从 fixture 输出倒推业务逻辑。
- 不在 `sketch_object.cpp` 中按几何类型、fixture 名称或 split 顺序做补丁。
- 不新增 `profiles[]`。
- 不接受 `FullSubList`。
- `StableSubList` 是正式字段，不是旧 payload 兼容。
- 面域、open wire、split history、stable subname 的通用能力应落在 `geometry/` 与 `topo/`，executor 只串联 FreeCAD 业务调用顺序。
