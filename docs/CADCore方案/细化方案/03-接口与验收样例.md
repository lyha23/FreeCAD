# 接口与验收样例

本文固定完整 CAD Core 抽取过程中的调用接口、输入输出形态、diagnostics、fixture 和 oracle 验收口径。CLI / C ABI / Web / WASM / Worker 都只是 adapter；同一份 `DocumentObject graph` 通过不同 adapter 调用，核心结果应一致。

## 接口边界

CAD Core 的稳定边界是：

```text
input:
  DocumentObject graph
  recompute target
  export options

output:
  object status
  diagnostics
  mesh / bbox / volume
  subshape map
  named_shapes runtime ledger
  stable subname
  optional adapter artifact path
```

不进入接口持久层：

- 裸 `TopoDS_Shape`。
- BREP 持久字段。
- NamedShape / ElementMap 跨请求状态。
- GUI selection / ViewProvider / TreeView 状态。
- Web session / user / JWT / database state。

## CLI 命令

主命令：

```bash
cad-core recompute fixtures/mvp/rect-pad.json --output out/rect-pad.result.json
```

阶段 fixture 使用同一命令：

```bash
cad-core recompute fixtures/p2/rect-pad-pocket.json --output out/rect-pad-pocket.result.json
cad-core recompute fixtures/p3a/pocket-up-to-face.json --output out/pocket-up-to-face.result.json
```

后续如果需要独立导出命令，只能作为 adapter 便利层：

```bash
cad-core export-mesh input.json --object Body --output out/Body.mesh.json
cad-core inspect-subshape input.json --object Body --subname Face1 --output out/Face1.json
```

这些命令不得引入不同于 `recompute` 的业务语义。

## C ABI

C ABI 保持薄桥接：

```c
CadResult* cad_core_recompute_json(const char* request_json);
const char* cad_core_result_json(const CadResult* result);
void cad_core_free_result(CadResult* result);
```

规则：

- C ABI 不保留跨请求 `DocumentHandle` 语义，除非后续显式加入 revision / property hash / cache 失效规则。
- C ABI 不直接暴露 OCCT handle。
- C ABI 返回 JSON 结构应和 CLI 输出对齐。

## Diagnostics 约定

错误输出必须适合自动测试，不只放自然语言：

```json
{
  "severity": "error",
  "code": "unsupported_property",
  "object": "Pad",
  "property": "SideType",
  "message": "Only SideType=One side is supported in this stage"
}
```

当前至少固定这些 code：

```text
parse_error
duplicate_object_name
duplicate_object_id
missing_property
missing_object
missing_link_target
cycle_dependency
unsupported_type
unsupported_property
unsupported_geometry
open_profile
invalid_length
invalid_subshape
unsupported_subshape_kind
execution_failed
unsupported_stable_subname
split_stable_subname
deleted_stable_subname
```

后续阶段新增 diagnostics 时要保持两个规则：

- 正常 fixture diagnostics 必须为空。
- 错误 fixture 断言 code，不依赖完整自然语言。

## Fixture 分层

```text
fixtures/mvp   P0/P1 frozen baseline
fixtures/p2    FeatureBase / FeatureAddSub / Pocket
fixtures/p3a   FeatureExtrude ThroughAll / UpToFace / UpToShape
fixtures/p3b   Two sides / Symmetric / UpToFirst / UpToLast / taper / custom direction / placement
fixtures/p4    Document / Property / Link / Placement
fixtures/p5    Sketch internals / external geometry
fixtures/p6    NamedShape / ElementMap / topo naming
fixtures/p7    Datum / Origin / Refine / Hole / Fillet / Chamfer / Pattern；当前先覆盖 CoordinateSystem / Origin 基础坐标、Refine=false no-op、Refine=true RefineModel 缺口 diagnostics、Hole 平底圆柱盲孔 / 通孔 / 无 base / threaded known gap、Fillet / Chamfer 的 Edge Base 成功和基础错误 diagnostics、Mirrored Features 模式和 WholeShape known gap、LinearPattern Features 的单方向 / 双方向 / 自定义 Spacings / SpacingPattern、PolarPattern Features 的 Extent / SpacingPattern / WholeShape known gap、Scaled Features / Factor diagnostics / WholeShape known gap，以及 MultiTransform Features 的乘法组合、Scaled diagonal 组合和 divisor diagnostics
fixtures/p8    Part / import-export / Assembly
```

每个 fixture 应说明：

- 输入 document graph。
- 对应 FreeCAD oracle。
- 正常 / 错误状态。
- 断言范围：bbox、volume、topology count、diagnostics、subshape / stable subname。
- 如果只接受命名顺序差异，要明确标注为非失败项。

## 当前验收清单

基础回归：

- `empty.json`：命令成功，diagnostics 为空。
- `unknown-type.json`：返回 `unsupported_type`。
- `missing-profile.json`：返回 `missing_property`、`missing_link_target` 或 `missing_object`。
- `open-sketch.json`：返回 `open_profile`，不生成 Pad artifact。
- `rect-pad.json`：返回 Pad mesh、subshape map、bbox，diagnostics 为空。
- `rect-pad-pocket.json`：返回 Body cut 后 bbox、volume、mesh、subshape map，diagnostics 为空。

P3a 回归：

- `pocket-through-all.json`：返回 Pocket `ThroughAll` 后的 Body bbox、volume、topology count，diagnostics 为空。
- `pocket-up-to-face.json`：`UpToFace` 通过 `PropertyLinkSub` 的 `FaceN` 解析真实 face，结果与 FreeCADCmd 几何对照一致。
- `pocket-up-to-shape-solid.json` / `pocket-up-to-shape-face.json`：单 full solid 和单 face 目标都能生成 cut 后 Body。
- `up-to-face-missing-subshape.json` / `up-to-face-edge-subshape.json`：分别返回 `invalid_subshape` / `unsupported_subshape_kind`，不把 Edge 当 Face 使用。
- `pad-up-to-face.json`：至少一个 Pad UpTo case 通过，且仍复用 shared `FeatureExtrude`。
- `pad-through-all-unsupported.json`：Pad 不误用 Pocket 的 `ThroughAll` 枚举，返回 `unsupported_property`。

后续阶段新增清单放到对应 P3b-P8 文档，并在阶段完成后回填本文件的 fixture 分层或关键命令。

## Oracle 规则

- 涉及 FreeCAD parity 时，先读本仓库 `src/` 中对应 App / Mod 源码。
- 只有证明采集脚本或 expected 错了，才改 oracle expected。
- 不允许按 cad-core 当前输出倒推 expected。
- sandbox 中 FreeCADCmd / Qt 报错不能直接当作实现失败；需要本机非 sandbox FreeCADCmd 输出作为 oracle 依据。
- 几何等价但 `InternalFaceN` / `InternalEdgeN` 顺序不同，归类为命名顺序差异；数量、几何内容、稳定 subname 丢失仍算失败。
