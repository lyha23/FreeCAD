# 接口与验收样例

本文件固定 CAD Core 的输入、输出、fixture 和 diagnostics 口径。它不是实现日志；新增能力只在这里补充验收分层和稳定错误码。

## CLI

```bash
cd /Users/li/Chili3DProject/重构Chili/FreeCAD/cad-core
./cad-core recompute fixtures/mvp/rect-pad.json --output out/rect-pad.result.json
```

输入是完整 `DocumentObject graph`，不是局部操作命令。`recompute.objs` 只表示本次计算目标。

## C ABI

`cad_core_ffi` 是薄 adapter。它应和 CLI 调用同一个 core recompute 入口，返回同一类 JSON 结果和 diagnostics。C ABI 不直接解析 FreeCAD 业务属性，不保存 shape，也不补拓扑命名。

## 输入规范

```json
{
  "Objects": [
    {
      "Name": "Pad",
      "ID": 2,
      "TypeId": "PartDesign::Pad",
      "Properties": {
        "Profile": {
          "PropertyType": "App::PropertyLinkSub",
          "value": "Sketch",
          "SubList": []
        },
        "Type": "Length",
        "Length": 10
      }
    }
  ],
  "recompute": {
    "objs": ["Pad"]
  }
}
```

规则：

- `Objects[]` 中的 `Name` 是运行时引用 key。
- `TypeId` 决定 executor。
- `Properties` 沿用 FreeCAD 属性名。
- `PropertyLink*` 归一为 dependency edge。
- `StableSubList` / `FullSubList` 可与 `SubList` 并存，用于 topo naming 引用恢复。

## 输出规范

结果至少包含：

```text

mesh
subshapes
named_shapes
diagnostics

```

diagnostics 字段口径：

```text

object
property

```

## 验收规则

- 正常 fixture diagnostics 必须为空。
- 错误 fixture 的 diagnostics code 必须稳定。
- 几何 fixture 优先校验 bbox、volume、topology count、subshape / named shape 语义。
- FreeCAD oracle 不可用时，必须在 fixture 或测试名中明确 known gap。
- 文档、fixture 和 tests 必须同步更新。
