# P8：Part、导入导出与 Assembly 后续

P8 已覆盖 Part primitives、BREP / STEP / IGES / STL 导入、BREP / STEP / STL CLI 导出、常用 Part Boolean、source-backed Part surface first batch（`Part::Loft`、`Part::Sweep` / PipeShell、`Part::FilledFace` helper 与 `Part::GeomPlateSurface` helper）、基础 Link / LinkSub / LinkGroup / LinkElement display、ShowElement 请求内子元素合成与 `documentObjectUpdates` 建议、`PropertyXLink*` / `FullSubList` / mapped postfix alias、`App::DocumentObjectGroup` plain group 展开、Assembly display、Joint 输入元数据、硬依赖 real Ondsel adapter 与 stateless placement writeback。C ABI capabilities 已暴露当前 `topo_history` 子集、`part_workbench.sweep`、`part_workbench.filling`、`part_workbench.geomplate` 与 Assembly solver real request-local 子集（Fixed / Revolute / Cylindrical / Slider / Ball / Distance / Angle），供前端区分可依赖的 stable subname / maker history 子集、request-local solver 子集和完整 MapperHistory / oracle-blocked Joint 证据缺口。Assembly native FreeCAD placement oracle 已写入并通过 `cad-core/fixtures/c3m6/expected`；C7-M6 已把非 identity connector / object-global 到 part-local marker chain 裁为 expected-backed closed，zero Angle fallback class evidence 和 bundled `offsetPlc` preDrag lifecycle 继续 `oracle_blocked`，没有打开 C++ implementation gate；完整 FreeCAD Link 账本、持久写回事务和产品化 adapter 仍保持后置。

本轮新增 `App::DocumentObjectGroup` plain group Link 展开：CAD Core 现在能把 `App::Link.LinkedObject` 指向的 plain `DocumentObjectGroup.Group` children，以及显式 `ElementList` 内 plain group 的 children，递归聚合为请求内 display compound，并保留 group 容器 executor 的 children 元数据、flattened index、group path、object-name 和 `$Label` LinkSub alias。该能力对齐 FreeCAD `LinkBaseExtension::linkedPlainGroup()` / `updateGroup()` 的请求内 `_ChildCache` display 与拾取边界，不声明完整 `_ChildCache` 持久生命周期、copy-on-change / linked-owner 矩阵或持久写回生命周期。

Part 当前边界：

- `Part::Extrusion` 的普通 prism 和 taper 现在发布 `NamedShape` maker-history 子集：普通 prism 走 `TopoShape::makeElementPrism()` 对应的 `BRepPrimAPI_MakePrism` history，taper 复用 P6 `BRepOffsetAPI_ThruSections` / `MapperThruSections` history；Solid=true 从 wire 造 face 仍只保留 source-edge preserved 子集，完整 FaceMaker history 继续归 P5/P6。
- 二元 boolean：`Base` / `Tool` 输入走 OCCT maker history 主路径，`Refine=true` 时复用当前 RefineModel 子集。
- `Part::Section`：输出 section edges compound，并保留 section maker history。
- `Part::MultiFuse` / `Part::MultiCommon`：按 `Shapes` 链接列表读取请求内 shape；`MultiFuse` 可展开单 compound 输入，`MultiCommon` 以 `CommonOfAllShapes` 为默认语义。
- `Part::XOR` / `Part::FeatureXOR`：作为 BOPTools `FeatureXOR` alias，走 Fuse / Common / Cut 组合主路径，当前只支持 `Tolerance=0`；expected oracle 使用 FreeCADCmd `BOPTools.SplitFeatures.makeXOR()` native proxy。
- `Part::BooleanFragments` / `Part::FeatureBooleanFragments`：支持 `Mode=Standard`、`Mode=Split` 的 solid-safe / wire aggregate / shell aggregate / CompSolid aggregate 子集、`Mode=CompSolid` 和非负 `Tolerance`；expected oracle 使用 FreeCADCmd `BOPTools.SplitFeatures.makeBooleanFragments()` native proxy。
- `Part::Sweep`：发布 source-backed DocumentObject first batch，读取 `Sections`、`Spine`、`Solid`、`Frenet`、`Transition`、`Linearize`，其中 `Spine` 支持 `PropertyLinkSub.SubList` 合成 compound，`Sections` 首批支持 one profile，PipeShell 使用 maker `Modified/Generated` history 生成 `NamedShape`。当前 capability 只列 S1 的 8 个 `c3m4` fixtures 和 invalid diagnostics；`Linearize=true` post-processing、advanced `BRepOffsetAPI_MakePipeShell` wrapper、auxiliary spine、located profile、support、trihedron/binormal 和 Hole `ModelThread` 内部 PipeShell 仍非目标。
- `Part::FilledFace`：cad-core helper 请求类型，对齐 FreeCAD `Part.makeFilledFace()` / `TopoShape::makeElementFilledFace()`，不是原生 FreeCAD DocumentObject；读取 `Boundary` / `App::PropertyLinkSubList`，首批只发布默认参数 closed wire、connected boundary edges、`BRepOffsetAPI_MakeFilling`、`maker_history:filling`、boundary source evidence 和 invalid diagnostics。`surface`、`supports`、`orders`、non-boundary constraints、non-default params、compound optional case 和完整 Part surface family 仍为 deferred / blocked。
- `Part::GeomPlateSurface`：cad-core helper 请求类型，对齐 FreeCAD `Part.GeomPlate.BuildPlateSurface()` / `CurveConstraint` / `PointConstraint` / `GeomPlate_MakeApprox`，不是 GUI 或 native `Part::GeomPlate` DocumentObject；首批只发布 source-backed 3D G0 curve constraints、3D point constraints、默认 / 显式 build params、approx surface metadata、source evidence、可转 face 的 expected 和 invalid diagnostics。initial surface、G1 curve-on-surface、projected 2D curve、custom criteria、`Part.PlateSurface(Curves=...)` 和完整 Part surface family 仍为 deferred / blocked。

Link / Assembly 当前边界：

- `App::Link` 支持 `LinkedObject`、`LinkTransform`、`LinkPlacement` / `Placement`、基础 `Scale` / `ScaleVector`；当两者同时存在时按 FreeCAD `getScaleVector()` 语义以 `ScaleVector` 为实际缩放，`Scale` 只作为无 `ScaleVector` 时的 fallback；并可解析 `LinkedObject.SubList` 中单个或多个 current / stable subname；多个 subshape 会在本次请求内组合为 compound，并保留源对象 alias retag。
- 直接 `$Label` 指向实体对象的 LinkSub native collector 会去掉当前 target 自身 Label token 后喂给 FreeCADCmd，以固定几何 oracle；目标为 `App::Link` 的多层 object / label 链仍保持 source-equivalent expected，因为 FreeCADCmd 原生属性赋值不会保留中间 Link placement，不能作为 native geometry oracle。
- `App::LinkElement` 复用 linked-object、transform、placement 和 scale 语义，输出带源对象 alias retag 的元素 shape。
- `App::LinkGroup` 和带 `ElementList` 的 `App::Link` 聚合请求内元素 shape，支持 group placement、`VisibilityList`、元素对象名、数字下标和 `$Label` LinkSub alias；`VisibilityList` 只影响 display，不阻断 LinkSub 解析。LinkGroup native expected collector 走 FreeCAD `LinkBaseExtension::setLink()` / `setElementVisible()`，ownerless fixture `LinkElement` 在 collector 内用 native `App::Link` 代理，避免直接写 `ElementList` 触发 FreeCADCmd 崩溃。
- `App::Link.LinkedObject -> App::DocumentObjectGroup` 和显式 `ElementList` 内 plain group 已按 FreeCAD `linkedPlainGroup()` / `updateGroup()` 递归展开 `Group` children，并保留 flattened index、group path、child object-name / `$Label` LinkSub alias；当前只覆盖请求内 display compound、nested child subshape picking 与 group executor metadata，不覆盖完整 `_ChildCache` 持久生命周期、copy-on-change / linked-owner 矩阵或完整 Link lifecycle。
- `App::Link` 的 `ElementCount` 折叠数组路径支持 `PlacementList`、`ScaleList`、`VisibilityList`、link placement / scale 和源对象 alias retag；`1.Face1` 和 `1.Box.Face1` 这类数字下标 LinkSub 会映射到对应折叠元素，且 `VisibilityList=false` 不阻断 LinkSub 解析，`Box.Face1` / `$PrettyBox.Face1` 这类 linked target 前缀会按 FreeCAD `getElementIndex()` 语义重定向到第 0 个折叠元素；`ShowElement=false` 时按 FreeCAD `LinkBaseExtension::update()` 的 resize 规则返回 owner `PlacementList` / `ScaleList` / `VisibilityList` 同步建议。
- `ShowElement=true` 已支持同文档中 `Owner_iN` 形式、`_LinkOwner` 匹配或空 owner 的已物化 `LinkElement` 子对象认领与聚合；已物化子元素按 owner `App::Link` 继承 `LinkedObject` 和 `LinkTransform` 并补请求内依赖边；单独 `LinkElement.Shape` 消费 owner `PlacementList` / `ScaleList`，其中 `ScaleList[i].x` 按 FreeCAD `LinkElement.Scale` 作为 uniform scale 使用。
- `ShowElement=true` owner `App::Link.Shape` 按 FreeCAD Shape 收集边界只使用 child placement / 默认 placement 和 `VisibilityList`，不把 child `ScaleList` 放大计入 owner Shape；native expected collector 通过 `setElementVisible()` 恢复只读 `VisibilityList`，并把 fixture `_LinkOwner` 映射到 FreeCAD `DocumentObject::getID()` 后再认领 child。
- `ShowElement=true` 缺失 `Owner_iN` 子对象时，会按 FreeCAD `LinkBaseExtension::update()` 的命名、`PlacementList`、默认 placement 和 `VisibilityList` 规则合成请求内 display 元素；`documentObjectUpdates` 同步返回缺失子元素 create、空 owner / owner=0 子元素 claim、已物化子元素属性 update、超出 `ElementCount` 的 owned child delete 建议。`ShowElement=true` 且显式 `ElementList` 已存在时，若 owner `ElementCount` 或 `VisibilityList` 长度与 `ElementList` 不一致，返回 owner sync 建议；若 child `LinkElement` 的 `_LinkOwner`、`LinkedObject` 或 `LinkTransform` 与 owner 不一致，返回 child sync 建议，但不在这条分支改 child placement / scale；当 child `LinkCopyOnChange=2` / `CopyOnChangeOwned` 时，只同步 `_LinkOwner` 和 `LinkTransform`，不覆盖 child 自有 `LinkedObject`。`ShowElement=false` 但旧 `ElementList` 仍保留时，会按 FreeCAD toggle-off 分支把 child placement / scale 收回到 owner list，清空 `ElementList`，并建议删除 owned child；本次 shape 也使用收回后的折叠 ElementCount 状态。合成或收回的元素只出现在本次响应的 group shape、metadata 和 `NamedShape` source alias 中，CAD Core 不在后端持久化或隐式改写请求 `DocumentObject graph`。
- `ShowElement=true` 子元素已把 `1.Face1` 和 `1.Box.Face1` 这类数字下标 LinkSub 写入 `NamedShape` source alias；该路径使用 FreeCADCmd native geometry oracle 固化。
- `PropertyXLinkSub.FullSubList` 已进入 document parser、C ABI `PropertyXLink*` capabilities 与 `elementReferenceUpdates`，并作为精确 alias 写入 Link subshape 的 `NamedShape.element_map`，用于保留请求里已经提供的完整 subname；`PropertyXLinkList` 已按 FreeCAD `PropertyXLinkList::setPyObject()` 的 object-only `values` 与 sub-element `SubSet` 双形态解析；`ElementCount` 折叠数组的非零 index 已写入 `;:I{idx}` mapped postfix alias，显式外部 full subname 已写入 `;:X;...` external-tag mapped postfix alias；Link retag 会传播上游 split / deleted terminal history 和 merge history，避免后续 stable subname 诊断降级为 unsupported，并保留 Body boolean merge 的原 source ledger；`BoxLink.Box.Face1`、`$PrettyBox.Face1`、`$PrettyChain.$PrettyBoxLink.$PrettyBox.Face1` 和 `LinkGroup.$PrettyB.$PrettyBox.Face1` 这类对象名 / Label 前缀 LinkSub 会先按 FreeCAD `getSubObject()` 路由剥离 linked object token，再沿源对象 `NamedShape` alias 解析；完整 cross-document 文档哈希生命周期和更复杂 LinkSub 链尚未迁移。
- `Assembly::JointGroup` 和 Assembly Joint / GroundedJoint 已进入 request-local solver input 边界：FreeCAD 中 Joint / GroundedJoint 是 `JointObject.py` 挂在 `App::FeaturePython` 上的动态属性，cad-core 固定 `JointType`、`Reference1` / `Reference2`、hidden `PropertyXLinkSub`、`ObjectToGround`、solver DTO 和 placement writeback metadata；当前构建硬依赖 bundled OndselSolver 并只执行 real Ondsel adapter。collector 已在 `cad-core/fixtures/c3m6/expected` 固化 10 个 native solver placement expected，覆盖 Fixed / Revolute / Cylindrical / Slider / Ball / Distance / Angle 子集；这些文件是后续修 cad-core parity 的标准答案，不再用 cad-core focused runtime 输出倒推 FreeCAD golden。
- `ShowElement=true` 自动创建 / 认领 / 同步 / 删除 `LinkElement` 的请求内建议、显式 `ElementList` owner `ElementCount` / `VisibilityList` sync、显式 `ElementList` child `_LinkOwner` / `LinkedObject` / `LinkTransform` sync 及 `CopyOnChangeOwned` child target 保留、`ShowElement` true->false owner list 收回与 owned child delete，以及 `ShowElement=false` ElementCount owner list resize sync 已迁移；完整写回事务和 FreeCAD Link 账本生命周期尚未迁移。

`fixtures/p8` 覆盖 Part primitive、Import / Export、Part Boolean、Section / XOR / BooleanFragments native oracle、基础 Link display、LinkSub 路由与 alias、hidden / XLink 解析、ElementList / ElementCount / ShowElement 请求内生命周期建议、plain group 展开、错误 diagnostics、Assembly display、Joint / GroundedJoint solver input metadata 和旧 `PropertyXLinkSubHidden` Joint reference metadata。`fixtures/c3m4` 覆盖 source-backed Part surface first batch，其中 Sweep 发布 8 个 case，Filling 发布 3 个 case：`part-filling-closed-wire-default`、`part-filling-boundary-edges-default`、`part-filling-invalid-inputs`，GeomPlate 发布 2 个 case：`part-geomplate-curve-point-default`、`part-geomplate-invalid-inputs`。`fixtures/c3m6` 覆盖 Assembly solver / placement writeback 的 focused runtime contract，且 `expected/` 已保存并验收 10 个 FreeCADCmd native solver placement oracle；当前没有 `known_gap` native placement expected。具体 fixture 名称以 `cad-core/fixtures/{p8,c3m4,c3m6}` 和 `cad-core/tests/test_p8_features.py` 为准。

## 边界

- 文件导入导出可以处理 BREP，但 BREP 不进入持久 `DocumentObject graph` 的默认状态模型；导出是 adapter 对本次计算 shape 的文件写出，不是前后端状态同步协议。
- Web / Worker / WASM 只做 adapter，不改变 CAD Core 无状态边界。
- Assembly 不应绕过 topo naming；Joint 的 subname 和 placement 仍需要稳定引用模型。
- 当前 Part primitive 和导入 shape 仍使用 indexed `NamedShape`；Link / LinkSub / LinkGroup / LinkElement 已有 source alias retag、前端图更新建议和 terminal / merge history 传播；Part Boolean 已消费 boolean / section / generalFuse maker history。导入 shape 完整 ElementMap、完整 FreeCAD Link 账本、`ShowElement=true` LinkElement / LinkGroup 持久写回事务生命周期、完整 cross-document 文档哈希生命周期和更复杂 LinkSub 链仍属于 P6/P8 后续工作。
