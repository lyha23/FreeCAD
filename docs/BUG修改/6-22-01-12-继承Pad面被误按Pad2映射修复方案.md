# 继承 Pad 面被误按 Pad2 映射修复方案

## 当前结论

这次补充信息很关键：用户实际点击的不是第二个面拉伸 `Pad2` 自己生成的面，而是最终 `Pad2Body` 上仍然来自第一个 `Pad` / `Fillet` 链路的面。

因此问题不应简化成“后端没有给 `Pad2.` 前缀”。从当前前端日志看，后端已经返回了可区分 owner 的路径：

```json
{
  "profileRef": {
    "objectName": "Pad2Body",
    "indexed": "Face11",
    "subname": "Fillet.Face11",
    "stableSubname": "Fillet.Face7"
  },
  "selectedFaceShape": {
    "id": "Pad2Body:Face11",
    "indexed": "Face11",
    "kind": "Face",
    "subname": "Fillet.Face11",
    "stableSubname": "Fillet.Face7"
  },
  "sourceChain": {
    "sourceObjectName": "Pad2",
    "dressUps": [
      { "kind": "fillet", "objectName": "Fillet", "baseObjectName": "Pad" },
      { "kind": "face-pad", "objectName": "Pad2", "baseObjectName": "Fillet" }
    ]
  },
  "targetObjectName": "Pad2"
}
```

这里 `Pad2Body:Face11` 只是当前显示结果里的枚举 token；它不能证明这个面属于 `Pad2`。真正的可引用 owner 由 `subname/stableSubname` 表达：`Fillet.Face11` / `Fillet.Face7` 说明该面当前应先按 `Fillet` 子形状处理。

当前前端把 `sourceChain.sourceObjectName = "Pad2"` 当成唯一重定向目标，导致它尝试把 `Fillet.Face11` 剥成 `Pad2` 局部 face。剥不出来后抛出：

```text
所选实体面无法映射到后端特征子形状，请重新选择可引用面
```

这个失败不是用户选错面，而是面拉伸的“Profile owner 选择规则”过窄。

## 字段语义

- `id = "Pad2Body:Face11"`：渲染 / 拾取 token，说明它是当前 Body result 的第 11 个 Face。
- `indexed = "Face11"`：当前 Body result 的枚举名，服务于 mesh faceIds / subshapes 对齐。
- `subname = "Fillet.Face11"`：后端给出的当前可引用对象路径，说明这个显示面来自 `Fillet` 的当前子形状。
- `stableSubname = "Fillet.Face7"`：可用于后续稳定引用或写回的路径，仍然落在 `Fillet` 命名空间。
- `sourceChain.sourceObjectName = "Pad2"`：当前 solid chain 的 Tip，不等于本次选中面的 owner。

结论：`sourceObjectName` 只能表达“后续特征追加在当前实体链 Tip 之后”，不能直接作为“所选 Profile 必须引用的对象”。

## 当前前端失败链路

涉及代码：

- `/Users/li/Chili3DProject/my-chili3d/src/lib/command/create/extrude/index.ts`
  - `selectedFaceInputFromSourceShapes()`
  - 当前把 `retargetCadProfileRefToObject(profileRef, sourceChain.sourceObjectName, ...)` 作为唯一路径。
- `/Users/li/Chili3DProject/my-chili3d/src/lib/services/cad-recompute/subshapes.ts`
  - `cadFaceProfileRef()` 保留了 `subname/stableSubname`。
  - `retargetCadProfileRefToObject()` 要求目标对象名能从 subshape path 里剥离。
- `/Users/li/Chili3DProject/my-chili3d/src/lib/feature/features/extrude/build.ts`
  - feature rebuild 时也使用相同的 target retarget 逻辑。
- `/Users/li/Chili3DProject/my-chili3d/src/lib/feature/features/dress-up-chain.ts`
  - chain replay 时的 `facePadInputFromFeature()` 同样需要按保存后的 Profile owner 重建。

失败流程：

1. 用户在最终 `Pad2Body` 上点击一个来自第一个 `Pad/Fillet` 链路的面。
2. `cadFaceProfileRef()` 得到 `objectName = "Pad2Body"`、`subname = "Fillet.Face11"`。
3. `resolveCadDressUpChain()` 根据 runtime result 得到当前 Tip：`sourceObjectName = "Pad2"`。
4. 前端把重定向目标固定为 `Pad2`。
5. `retargetCadProfileRefToObject()` 只能从 `Fillet.Face11` 剥 `Fillet`，剥不出 `Pad2`。
6. 前端报错。

第 4 步是核心 BUG。

## 推荐修改方案

### 1. 新增“选择面 owner”解析

在前端 cad-recompute subshape 工具层增加一个明确函数，例如：

```ts
resolveCadProfileRefOwnerInChain(profileRef, sourceChain)
```

职责：

1. 从 `profileRef.subname` 的第一段对象路径解析候选 owner，例如 `Fillet.Face11 -> Fillet`。
2. 如果 `subname` 无法解析，再尝试 `stableSubname`，例如 `Pad.Face6 -> Pad`。
3. 候选 owner 必须存在于当前 solid chain：
   - base object：`Pad` / `Revolution`。
   - chain item：`Fillet`、`Chamfer`、`Pad2`、后续 face-pad / face-revolve。
4. 候选 owner 的 local subname 必须与当前拓扑 kind 匹配：Face 只能映射到 `FaceN`，不能接受 `EdgeN` / `VertexN`。
5. 如果没有明确 owner，保持快速失败，不做几何猜测。

对当前数据应得到：

```json
{
  "profileOwner": "Fillet",
  "profileRef": {
    "objectName": "Fillet",
    "indexed": "Face11",
    "subname": "Face11",
    "stableSubname": "Face7"
  }
}
```

### 2. 面拉伸创建入口使用 owner，而不是固定用 Tip

把当前逻辑：

```ts
retargetCadProfileRefToObject(profileRef, sourceChain.sourceObjectName, source)
```

改成两步：

```ts
const profileOwner = resolveCadProfileRefOwnerInChain(profileRef, sourceChain)
const documentProfileRef = retargetCadProfileRefToObject(
  profileRef,
  profileOwner,
  source,
)
```

这样：

- 点到 `Pad2.Face1` 这类 `Pad2` 新生成面时，`profileOwner = "Pad2"`。
- 点到 `Fillet.Face11` 这类继承面时，`profileOwner = "Fillet"`。
- 点到 `Pad.FaceN` 这类更早源面时，`profileOwner = "Pad"`。

后续 feature 仍追加在当前 solid chain 之后；只是 `Profile.value` 应引用实际承载该面的对象。

### 3. preview / rebuild / chain replay 三处必须同步

只改命令入口会留下保存后重建失败。需要同步：

1. 创建命令选中面时写入正确的 `options.profileRef.objectName`。
2. preview 调 `/cad/recompute` 时使用已解析的 `documentProfileRef`。
3. `buildCadFacePadExtrudeFeature()` 重建时不要重新把 profile 强制 retarget 到 `sourceChain.sourceObjectName`。
4. `facePadInputFromFeature()` replay chain 时以保存的 `profileRef.objectName` 为准，同时校验它仍在当前 chain 中。

如果保存的 `profileRef.objectName` 已经是 `Fillet`，后续重建不应再把它改成 `Pad2`。

### 4. 保留后端契约保护

后端仍要满足：

- Body result 的 `subshapes[].subname` 尽量带当前可引用 owner path，例如 `Fillet.Face11`、`Pad2.Face1`。
- `id/indexed` 继续锚定显示 Body，例如 `Pad2Body:Face11` / `Face11`。
- 不从 mesh 面片、面积、bbox 或顺序反推 owner。
- 不把继承自 `Fillet` 的面伪造成 `Pad2.Face11`。

如果后端未来返回裸 `Face11`，前端仍应失败并报 diagnostic；这代表后端缺少引用恢复信息。

### 5. 增加 focused 用例

前端测试建议覆盖三类面：

1. `Pad -> Fillet -> Pad2` 后，选择 `Pad2.Face*`：Profile owner 应为 `Pad2`。
2. `Pad -> Fillet -> Pad2` 后，选择 `Fillet.Face*` 继承面：Profile owner 应为 `Fillet`。
3. `Pad -> Fillet -> Pad2` 后，选择 `Pad.Face*` 直通源面：Profile owner 应为 `Pad`，前提是后端确实返回 `Pad.Face*` path。

每个 case 断言最终 `facePadCadDocument()` 里的 `Profile`：

```json
{
  "PropertyType": "App::PropertyLinkSub",
  "value": "Fillet",
  "SubList": ["Face11"],
  "StableSubList": ["Face7"]
}
```

不要断言 `value = "Pad2"`，除非选中的 `subname` 明确是 `Pad2.FaceN`。

## 非目标

- 不在前端把 `Fillet.Face11` 猜成 `Pad2.Face11`。
- 不把 `Pad2Body:Face11` 的 `indexed` 当作长期拓扑身份。
- 不靠 mesh 三角面、法向、面积、bbox 或点击位置猜 owner。
- 不修改 `edgeSegments` / `vertexPoints` / faceIds 的拾取 token 对齐契约。
- 不恢复旧 wasm / ShapeFactory / 单操作 OCC 路径。
- 不让后端为了这个场景丢掉 `Fillet.` / `Pad.` 这类真实 owner path。
