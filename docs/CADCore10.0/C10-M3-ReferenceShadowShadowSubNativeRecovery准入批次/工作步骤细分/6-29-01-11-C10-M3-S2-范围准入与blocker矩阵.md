# C10-M3-S2 范围准入与 blocker 矩阵

## 目标

把 S1 source candidates 路由到可执行 scope、blocker、non-goal 和 backend-gap category。S2 只做范围准入，不采 oracle，不改 C++，不把 `notCollected` 转成实现任务。

## 分类规则

| 路由 | 进入条件 | 下一步 |
| --- | --- | --- |
| `baseline_frozen_s0` | S0 已冻结起点 | S6 release gate 复核即可。 |
| `native_oracle_candidate` | 有 FreeCAD authority，但需要 FCStd / XML restore 证明 native 可观察 | S3 采集或复核 evidence。 |
| `current_comparison_pending` | S3 已有 native evidence 后，待比较 current cad-core | S4 比较 parser / recovery / diagnostic。 |
| `backend_gap_candidate` | S3-S5 证明 native evidence + current mismatch | S6 落 C++ / focused tests。 |
| `diagnostic_retained` | 语义无法 request-local 唯一恢复或 evidence 不足 | S6 发布诊断边界。 |
| `notCollected` | FreeCAD 行为不可观察或尚未采集 | 不实现，除非先补 oracle。 |
| `diagnostic_non_goal` | 本包明确排除 | 只记录 reopen condition。 |
| `release_gate` | 等待 S6 收口 | S6 同步 docs、capability、tests 和 queue。 |

## 必须回写的矩阵行

- `scope_review_matrix.tsv`：每个 scope 必须有合法 `current_status`、`next_step` 和 `close_condition`。
- `blocker_queue.tsv`：每个 blocker 必须指向至少一个 scope，并有 owner step。
- `non_goal_registry.tsv`：每个 non-goal 必须写清 user / protocol behavior 和 reopen condition。
- `backend_gap_classification.tsv`：不能出现没有 FreeCAD authority、native evidence 和 current mismatch 的 `backend_gap_requires_implementation`。
- `C10M3-BLOCKER-201`：S2 完成后改为 `closed_s2`。
