# CADCore5.1 PartDesign 剩余 deferred 语义一揽子方案

## 目标

把 C5 freeze 中剩余的 PartDesign deferred / non-goal 边界整体重开并分批实现。继续不实现 GUI Attachment editor；除此之外，Revolution / Groove、Boolean、Loft、Pipe、Datum Attachment / AttachEngine 和 AttachmentSupport shadow-sub writeback 都进入 C5.1 scope。

CAD Core 仍保持无状态后端：前端提交完整 `DocumentObject graph`；后端只基于本次 request graph、目标对象和输入 evidence 计算 shape、topo naming、diagnostics 和建议写回。AttachmentSupport shadow-sub writeback 不依赖后端会话，可以通过 request input 里携带 `StableSubList`、`ShadowSub`、`ReferenceShadow`、旧 subname 和当前 graph 来生成 `documentObjectUpdates` / `elementReferenceUpdates` 建议。

## AttachmentSupport input-driven writeback 设计

前端 request graph 应允许 `AttachmentSupport` 的 link 条目携带这些证据：

```json
{
  "property": "AttachmentSupport",
  "values": [
    {
      "value": "SupportObject",
      "SubList": ["Face1"],
      "StableSubList": ["Face1"],
      "ShadowSub": [{"oldName": "Face1", "newName": "Face3"}],
      "ReferenceShadow": {"subname": "Face1", "brep": "..."}
    }
  ],
  "MapMode": "FlatFace",
  "AttachmentOffset": {"position": [0, 0, 0], "rotation": [0, 0, 0, 1]},
  "MapReversed": false,
  "MapPathParameter": 0.0
}
```

cad-core 做三件事：

- 用当前 graph 的 support shape、`StableSubList`、`ShadowSub`、`ReferenceShadow` 恢复 attachment subshape。
- 用 selected `MapMode` 和 Datum engine type 计算本次 request 的 Datum placement。
- 如果 FreeCAD 同等规则会规范化 subname，则只返回建议更新，不直接修改持久 graph：`documentObjectUpdates` 写 `AttachmentSupport.SubList` / shadow evidence，`elementReferenceUpdates` 写下游引用建议。

这不是跨请求 session；所有恢复证据必须来自 input。

## 实施原则

- 先 native oracle，再 cad-core 行为；不得从 cad-core 当前输出倒推 expected。
- 先补正式 geometry / topo / mapper history 能力，再切 executor 主路径；不得在 adapter 或输出端补猜测。
- 每个 step 是最小完整语义批次：同一 FreeCAD 调用链、同一 DTO / API 边界、同一类 expected 一起收。
- 支持态必须同步 capability metadata、fixtures、focused tests、docs 和 freeze summary。
- 暂未完成的分支只能留下具体 blocker，不能恢复 broad PartDesign gap。
