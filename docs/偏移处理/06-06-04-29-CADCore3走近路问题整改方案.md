# CADCore3 走近路问题整改方案

时间：2026-06-06 04:29。

## 背景

本方案基于 `docs/代码review/5-25-07-46-WireJoiner自作聪明fallback实现反思.md` 的审查规则，对当前 `cad-core` 中仍带有“代表路径 / request-local / helper bridge / protocol writeback”特征的实现做整改规划。

这里的“走近路”不是普通默认值或 FreeCAD 明确公式，而是：

```text
缺少 FreeCAD 内部账本 / solver / object lifecycle
  -> 用 request-local 估算、代表性 placement、协议 update、helper output bridge 补上
  -> capabilities 或 docs 又把它说成 gap 已完整清空
```

这类实现可以作为阶段性切片，但不能伪装成 FreeCAD 完整等价语义。整改目标是把“阶段性可用”与“完整迁移完成”拆开，让代码、capabilities、docs 和验收命令的口径一致。

## 本轮执行范围

本轮已实施除 GCS / Sketch solver 外的口径整改：

- Assembly：`representative_solver_adapter.status=covered_representative`、`ondsel_solver_adapter.status=not_implemented`、`placement_writeback.status=covered_contract`；`assembly.remaining_gaps` 保留 `ondsel_solver_session`、`joint_constraint_solve`、`validated_new_placements`。
- Link CopyOnChange：`copy_on_change_writeback_contract.status=covered`、`copy_on_change_deep_copy_lifecycle.status=partial`；`link_transaction.remaining_gaps` 保留 property tree、child object、dependency relink、history preserve 四项。
- taper history：C ABI 新增 `object_metadata_gaps.local_history_gaps`，区分对象级 `known_gap:taper_history` 和顶层 CADCore3 broad `known_gaps=[]`。
- WireJoiner：`generated_open_export_bridge.status=bridge`、`purge_as_original_bridge.status=bridge`，并在代码注释中绑定删除条件；未新增 helper reason，未继续添加 fixture-shaped pruning。

本轮明确排除：

- 不实现 GCS solver。
- 不新增 `cad-core/src/sketcher/sketch_solver.cpp`。
- 不改 `requestLocalSolverDofFirstSlice` 主逻辑。
- 不处理 `full_solver_dof` / `request_local_solver_dof` / `gcs_solver_dof`。

## 总体整改原则

1. capabilities 不能用“空 gap”掩盖阶段性实现。

   如果实现是 `representative`、`request_local`、`first_slice`、`writeback_contract` 或 `helper_bridge`，capabilities 必须直接暴露这个状态。不能只因为 fixture 通过就把 `remaining_gaps` 清空。

2. 完整清 gap 的条件是 FreeCAD 字段生命周期被表达。

   对 solver、Link lifecycle、WireJoiner、ElementMap 这类语义，必须能说明：

   ```text
   FreeCAD 文件：
   FreeCAD 函数：
   关键字段：
   写入阶段：
   cad-core 等价结构：
   导出 / writeback 消费点：
   ```

3. 过渡桥可以保留，但必须有删除条件。

   过渡桥只能是为了保持当前验收不倒退，不能继续叠加新 fixture 形态规则。新增 case 暴露差异时，先补对应 FreeCAD 账本，不在桥上加第二层规则。

4. 文档要区分三种状态。

   - `covered_full`：FreeCAD 主语义已迁移。
   - `covered_representative` / `covered_request_local`：可用切片已覆盖，但不是完整等价。
   - `diagnostic_only` / `bridge`：只用于 trace 或保持兼容，不能作为长期目标。
