## 背景

本方案基于 `docs/代码review/5-25-07-46-WireJoiner自作聪明fallback实现反思.md` 的规则，对 `cad-core` 中已经出现的同类偏移做整改规划。

这里说的“偏移”不是普通 fallback、默认值或 FreeCAD 明确公式，而是：

```text
原本为了观察差异、补临时缺口或辅助诊断的实现
  -> 进入 InternalShape / NamedShape / ElementMap / Profile 解析 / subshapes 输出
  -> 成为用户可选、可引用、可持久追踪的正式主路径
```

判断标准很直接：如果逻辑只写 diagnostics 或 test trace，可以保留为诊断；如果它影响最终 shape、internal subshape、stable subname、profile selection 或 `ElementMap`，就必须按 FreeCAD 主语义迁移，不能继续用结果形态推断。

- 剩余 history 风险：WireJoiner 自己的完整 `aHistory`、`myShapesToReturn`、`findTightBound()` / `exhaustTightBound()` 分支搜索和 `WireInfo.done` 生命周期还没有完全迁移；当前 result-wire edge、splitter history summary、open-export source lineage summary、逐条 open-export producer entries、producer reason 分类 ledger 和 generated-to-consumed-EdgeInfo trace 已进入 topo context 并能满足现有 P5/P6 oracle，但 `generatedOpenExportShapeForSketchInternals()` 和 `purgeAsOriginalOpenEdge` 仍是过渡桥，不能继续扩展新 fixture 规则。`temporary_result_wire_edge_info_count`、`graph_fallback_assigned_edge_info_count` 与 `graph_secondary_owner_edge_info_count` 已归零；cross / segmented-cross / T-junction / three-overlap / arc-lens / bullseye 等 bounded-result case 仍有 `generated_open_export_edge_info_count`，且这些 generated open-export edge 当前被 `source_lineage_missing_open_export_edge_info_count` / `open_export_generated_missing_source_lineage_edge_count` 标出，说明删除 generated open-export 来源前还必须补完整 stack / wireSet 搜索、`myShapesToReturn`、copied result-wire identity 和 result-wire 生成历史。不要给 generated copy edge 再补 sourceEdgeArray lineage 作为替代；它必须由真实 `openWireCompound` / `MapperHistory(aHistory)` 生命周期产出。`findClosedWires(true)` adjacent-list stack、existing `wireInfo` hit / reverse-hit / purge trace、`findSuperEdgesUpdateFirst()` live lifecycle、`EdgeInfo::shape()` / `wire()` 入口、`findTightBoundWithSplit()` splitWire vertices trace、child-wire shared-vertex noOriginal 谓词、source-identity-only purge gate、generated bridge producer reason 和 generated-to-consumed-EdgeInfo trace 已切入；`purgeAsOriginalOpenEdge` 的删除条件仍是用真实 `aHistory` / `myShapesToReturn` 产出 generated result-wire identity，并替换 generated open-export 过渡来源。
- 已修正的非阻塞点：Profile 选择只在 open splitter 产生多个 InternalFace 时才要求 `Profile.SubList`；`getOpenWires(noOriginal)` 不再使用 endpoint-touch / boundary-touch 规则，through-open-cutter 的 2 face / 9 edge / 10 vertex 计数已恢复。

## 总体整改原则

1. 先补账本，再改导出。

   出现 `EdgeInfo`、`WireInfo`、`MapperHistory`、`ElementMap`、`myShapesToReturn`、`myPreSplitHistory`、`mySplitter` 这类 FreeCAD 内部账本时，不允许先在输出端按几何形态删改。

2. topo 层只消费 history，不发明 history。

   `topo/` 可以把 maker history、WireJoiner history、ElementMap ledger 转换成稳定 subname 和诊断状态，但不能靠 raw/internal shape 几何采样反推出业务 ownership。

3. fallback 只能是短期桥，不能叠规则。

   如果短期不能一次迁移完整 FreeCAD 状态机，fallback 必须写清适用边界、删除条件和不能新增第二条形态规则。

4. fixture 只做验收，不定义语义。

   任何规则进入主路径前，必须能回答：FreeCAD 文件、函数、字段、调用顺序、cad-core 落点、验证方式。

### 整改后流程

## 偏移 6：ReferenceShadow 恢复通道边界

### 当前流程

`ReferenceShadow` 当前用于：

- `feature_extrude.cpp` 中恢复 Pad/Pocket Profile 的 InternalFace；
- `sketch_object.cpp` 中恢复 ExternalGeometry 的 InternalEdge/InternalVertex；
- `topo/reference_matcher.*` 中通过 fingerprint 或 BREP snapshot 找唯一 subshape。

### 为什么需要单独处理

这不是普通错误 fallback。仓库规则已经批准 `ReferenceShadow.brep` 是唯一可以保存的单 subshape 旧几何快照，用作无状态引用恢复证据。

但它仍然有偏移风险：如果把它扩展成完整 BREP cache、建模输入、通用拓扑命名推断，就会破坏 CAD Core 无状态边界。

### 正确边界

允许：

- 只保存被引用的单个旧 subshape snapshot。
- 只用于引用恢复证据。
- 必须校验 target id、property、shape type、fingerprint / sha256 / byteLength。
- 只能在 `ElementMap` 无法恢复时作为 fallback。

禁止：

- 保存完整对象 BREP 作为建模输入。
- 用 ReferenceShadow 替代 FaceMaker/WireJoiner/MapperHistory。
- 用 BREP 匹配结果生成新的稳定命名规则。
- 在 response 中把 BREP 当长期几何状态输出。

### 整改动作

1. 给 ReferenceShadow 恢复路径增加统一封装，例如 `topo::recoverReferenceShadowSubshape()`。
2. 所有调用点必须先尝试 `NamedShape` / `ElementMap`，再进入 ReferenceShadow。
3. 恢复成功时输出明确 metadata：

   ```text
   reference_recovery = "reference_shadow_single_subshape"
   reference_recovery_reason = "element_map_missing_or_split"
   ```

4. 如果 `ElementMap` 已经能稳定恢复，不再走 ReferenceShadow。

### 验收点

- 单 subshape drift 能恢复。
- split / ambiguous / deleted 能明确诊断。
- 不出现完整 BREP 输入建模路径。
