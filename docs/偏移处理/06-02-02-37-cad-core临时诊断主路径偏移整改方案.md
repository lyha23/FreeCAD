# CAD Core 临时诊断主路径偏移整改方案

时间：2026-06-02 02:37。

## 背景

本方案基于 `docs/代码review/5-25-07-46-WireJoiner自作聪明fallback实现反思.md` 的规则，对 `cad-core` 中已经出现的同类偏移做整改规划。

这里说的“偏移”不是普通 fallback、默认值或 FreeCAD 明确公式，而是：

```text
原本为了观察差异、补临时缺口或辅助诊断的实现
  -> 进入 InternalShape / NamedShape / ElementMap / Profile 解析 / subshapes 输出
  -> 成为用户可选、可引用、可持久追踪的正式主路径
```

判断标准很直接：如果逻辑只写 diagnostics 或 test trace，可以保留为诊断；如果它影响最终 shape、internal subshape、stable subname、profile selection 或 `ElementMap`，就必须按 FreeCAD 主语义迁移，不能继续用结果形态推断。

## 当前偏移清单

| 序号 | 偏移点 | 当前落点 | 问题性质 | 整改结论 |
| --- | --- | --- | --- | --- |
| 1 | WireJoiner bounded-face ownership classifier | `cad-core/src/geometry/wire_joiner.cpp` | 用 bounded face 边界反推 `wireInfo` / `iteration` | 必须迁移真实 `EdgeInfo/WireInfo` 生命周期 |
| 2 | copied result-wire graph | `wire_joiner.cpp` + `sketch_internal_builder.cpp` | 按 closed cycle / endpoint / partial overlap 补 InternalShape edge | 删除输出端复制规则，改由 final EdgeInfo 导出 |
| 3 | `getOpenWires(noOriginal)` 兼容过滤 | `wire_joiner.cpp` | 用同坐标 endpoint 和 boundary-touch 旁路补 identity 缺口 | 改为 sourceEdgeArray / vertex identity / EdgeInfo source ownership |
| 4 | FaceMakerBuildFace fallback topology switch | `cad-core/src/geometry/face_maker.cpp` | 用 face count、shared boundary、topology split 选择替代 `myShapesToReturn` 账本 | BuilderFace / FaceMaker history 成为主路径，fallback 明确降级 |
| 5 | Sketch InternalShape ElementMap/history 几何合成 | `cad-core/src/topo/element_map.cpp`、`named_shape.cpp` | 从 raw/internal 几何关系倒推 split/generated/deleted history | topo 层只消费 FaceMaker/WireJoiner 产出的 history |
| 6 | ReferenceShadow BREP/fingerprint 恢复 | `feature_extrude.cpp`、`sketch_object.cpp` | 已进入 Profile / ExternalGeometry 主解析路径 | 保留为批准例外，但必须收窄为单 subshape 恢复通道 |

`cad-core/src/features/hole.cpp` 中的 `thread_*_fallback`、`thread_clearance_fallback` 不列入本次整改；这些是 FreeCAD `FeatureHole.cpp::Hole::determineDiameter()` 的业务公式或默认规则，不是诊断手段升级为主路径。

## 总体整改原则

1. 先补账本，再改导出。

   出现 `EdgeInfo`、`WireInfo`、`MapperHistory`、`ElementMap`、`myShapesToReturn`、`myPreSplitHistory`、`mySplitter` 这类 FreeCAD 内部账本时，不允许先在输出端按几何形态删改。

2. topo 层只消费 history，不发明 history。

   `topo/` 可以把 maker history、WireJoiner history、ElementMap ledger 转换成稳定 subname 和诊断状态，但不能靠 raw/internal shape 几何采样反推出业务 ownership。

3. fallback 只能是短期桥，不能叠规则。

   如果短期不能一次迁移完整 FreeCAD 状态机，fallback 必须写清适用边界、删除条件和不能新增第二条形态规则。

4. fixture 只做验收，不定义语义。

   任何规则进入主路径前，必须能回答：FreeCAD 文件、函数、字段、调用顺序、cad-core 落点、验证方式。

## 偏移 1：WireJoiner bounded-face ownership classifier

### 当前流程

当前主路径大致是：

```text
SketchObject
  -> buildOptionalProfileFace()
  -> buildSketchInternals()
  -> FaceMakerBuildFace 得到 bounded faces
  -> WireJoiner::classifyBoundedFaceOwnership(faceResult.shape)
  -> 按 face boundary 推断 edgeInfo.wireInfo / wireInfo2 / iteration=-3
  -> getOpenWires() 导出 leftover open wires
```

代码落点：

- `cad-core/include/cad_core/geometry/wire_joiner.h::WireJoiner::classifyBoundedFaceOwnership()`
- `cad-core/src/geometry/wire_joiner.cpp::WireJoiner::classifyBoundedFaceOwnership()`
- `cad-core/src/geometry/sketch_internal_builder.cpp::buildSketchInternals()`

### 为什么偏了

这条路径仍然在用“已经生成的 bounded face 边界”反推 WireJoiner ownership。它把本该由 FreeCAD `WireJoinerP::findTightBound()` / `exhaustTightBound()` 写出的状态，改成了：

```text
edge 是否匹配 face boundary
edge 是否 touch boundary
edge midpoint 是否在 bounded face 外
splitFromInputEdge 是否为 true
```

这些条件能解释某些 fixture，但不是 FreeCAD 的字段生命周期。

### 正确主路径

FreeCAD 依据：

- `/Users/admin/Chili3DProject/重构Chili/FreeCAD/src/Mod/Part/App/WireJoiner.cpp`
- `WireJoinerP::build()`
- `WireJoinerP::splitEdges()`
- `WireJoinerP::buildClosedWire()`
- `WireJoinerP::findTightBound()`
- `WireJoinerP::exhaustTightBound()`
- final open export 条件：`iteration == -3 || (!wireInfo && iteration >= 0)`

cad-core 目标流程：

```text
source/open wires
  -> WireJoiner EdgeInfo live list
  -> splitEdges 写 superEdge / source identity
  -> buildClosedWire 写 primary wireInfo
  -> findTightBound 写 ordered vertices / branch ownership
  -> exhaustTightBound 写 wireInfo2 / done 状态
  -> getOpenWires 只读 final EdgeInfo 状态
```

### 整改动作

1. 在 `geometry/wire_joiner.*` 中明确区分两类状态：
   - `FinalEdgeInfo`：真实主路径，参与导出。
   - `WireJoinerLedgerSummary`：诊断摘要，只写到 result metadata，不参与导出决策。

2. 迁移 `findTightBound()` 的最小可验证结构：
   - stable EdgeInfo id。
   - ordered vertex ledger。
   - `wireInfo` primary owner。
   - `iteration` / `iteration2`。
   - branch search candidate 到 owner 写入点。

3. 迁移 `exhaustTightBound()`：
   - `WireInfo.done`。
   - `wireInfo2` secondary owner。
   - done wire 的 shared edge 处理。

4. 删除或降级 `classifyBoundedFaceOwnership()`：
   - 不能再写 final export state。
   - 如果保留，只能生成 diagnostic 对比摘要，例如 `bounded_face_classifier_probe`。

### 验收点

- `getOpenWires()` 中不再出现 midpoint / boundary touch / bounded face ownership 推断。
- open export 只依赖 final `EdgeInfo` 字段。
- `wire_joiner_ledger` 仍可输出，但它不影响 shape。
- 用同一组 fixture 覆盖：
  - open cutter 被 closed face 消费。
  - closed boundary + branch cutter。
  - partial shared edge。
  - self/inter-edge split 同时存在。

## 偏移 2：copied result-wire graph 补进 InternalShape

### 当前流程

当前 `buildSketchInternals()` 在 `WireJoiner::getOpenWires()` 之后，还会调用：

```text
copiedResultWireGraphForSketchInternals()
  -> copiedResultWireGraph()
  -> copiedPartialSharedClosedWireEdges()
  -> copiedPartialJunctionResultWireGraph()
  -> compound 到 InternalShape
```

代码落点：

- `cad-core/include/cad_core/geometry/wire_joiner.h::copiedResultWireGraphForSketchInternals()`
- `cad-core/src/geometry/wire_joiner.cpp::copiedResultWireGraphForSketchInternals()`
- `cad-core/src/geometry/sketch_internal_builder.cpp::buildSketchInternals()`

### 为什么偏了

这条路径按以下几何形态补 edge：

- closed wire 数量；
- source edge 是否被 result edges 分裂；
- open edge endpoint 是否 touch boundary；
- partial overlap；
- edge 是否 lies on closed boundary 或 partial open edge。

这些 shape 会进入 `InternalShape`，再进入 `InternalEdgeN` / `InternalVertexN` / mesh / subshapes。它不是调试输出，而是正式拓扑结果。

### 正确主路径

FreeCAD 的 copied result-wire edge 应来自 `WireJoinerP::build()` 里的 final `EdgeInfo` live list。导出层不应复制 bounded face 的 edge 来补结果。

cad-core 目标流程：

```text
WireJoiner final EdgeInfo list
  -> openWireCompound / result-wire states
  -> SketchObject::buildInternals() compound(result, openWires)
  -> InternalShape
```

### 整改动作

1. 给 `EdgeInfo` 增加明确的 result-wire source 类型：
   - source original。
   - split from source edge。
   - copied result wire edge。
   - tight-bound consumed edge。

2. `copiedResultWireGraphForSketchInternals()` 先改名为 `copiedResultWireGraphProbe()` 并从主路径断开。

3. 在 `buildSketchInternals()` 中只接收 `WireJoiner` 返回的正式 open/result compound，不再单独从 bounded face shape 复制。

4. 若迁移期间必须保留，要求：
   - 注释写明临时 fallback。
   - 只允许一条规则。
   - 每个 fixture 使用该 fallback 时输出 diagnostic 标记。
   - 有明确删除条件：`WireJoiner` 能返回 final result-wire states 后删除。

### 验收点

- `InternalShape` 中新增的 open/result edges 均能追溯到 `EdgeInfo` id。
- `InternalEdgeN` / `InternalVertexN` 数量变化能由 `WireJoiner` trace 解释。
- 不再通过 closed-wire cycle、partial overlap、endpoint touch 判断是否复制 result wire。

## 偏移 3：`getOpenWires(noOriginal)` 的兼容性几何过滤

### 当前流程

当前 `getOpenWires()` 会先按 final-like 条件收集 live edges：

```text
edgeInfo.iteration == -3 || (edgeInfo.wireInfo == 0 && edgeInfo.iteration >= 0)
```

之后在 `noOriginal=true` 时，通过：

```text
allEdgesShareOriginalSourceVertex()
retainedByBoundaryTouchEdges
same-coordinate source endpoints
```

过滤 open wires。

### 为什么偏了

FreeCAD `getOpenWires(noOriginal=true)` 的核心是 source compound 与 current edge 的共享拓扑关系。当前实现因为 split/copy 后的 source identity 不完整，用同坐标 endpoint 做兼容判断。这会把“身份账本缺失”变成几何猜测。

### 正确主路径

FreeCAD 依据：

- `/Users/admin/Chili3DProject/重构Chili/FreeCAD/src/Mod/Part/App/WireJoiner.cpp::WireJoinerP::getOpenWires()`
- `sourceEdgeArray`
- `source.findSubShapesWithSharedVertex(TopoShape(edge, -1))`

cad-core 目标流程：

```text
addSourceEdge()
  -> sourceEdgeArray equivalent
  -> split/copy edge carries source EdgeInfo id
  -> noOriginal 只看 shared topological source vertex / source identity
```

### 整改动作

1. 在 split/copy 时保留 source edge id 和 source vertex id。
2. `getOpenWires(noOriginal)` 改成 identity first：
   - topological shared vertex。
   - source EdgeInfo id。
   - source vertex id。
3. same-coordinate 判断只允许留在 diagnostic：
   - 输出 `coordinate_match_only`，不参与删除/保留。
4. `retainedByBoundaryTouchEdges` 删除，改为 final `EdgeInfo` 的 export flag。

### 验收点

- 同坐标但不同拓扑 vertex 的 case 不会被误过滤。
- split fragment 的 noOriginal 行为能通过 source EdgeInfo id 解释。
- trace 能显示 source edge -> split edge -> final export 的完整链。

## 偏移 4：FaceMakerBuildFace fallback topology switch

### 当前流程

当前 `face_maker.cpp` 里同时存在：

```text
makeFaceWithHolesFromClosedWiresImpl()
buildBoundedFacesFromEdgeNetwork()
splitOverlappingFaces()
connectedSplitEdgesFromBoundary()
topologyWasSplit()
```

并通过 face count、shared boundary、split topology 等条件，在 fallback face 和 BuilderFace-like result 之间切换。

### 为什么偏了

FaceMakerBuildFace 的关键语义不是“哪个结果 face count 更像 fixture”，而是：

- `BOPAlgo_BuilderFace` 的 `myShapesToReturn`；
- `FaceMakerBuildFace::splitSelfIntersecting()`；
- `FaceMaker::postBuild()`；
- `MapperHistory(myPreSplitHistory)`；
- `MapperMaker(mySplitter)`。

当前实现有一部分已经在向 BuilderFace 靠拢，但仍在用结果 shape 条件决定主路径。

### 正确主路径

FreeCAD 依据：

- `/Users/admin/Chili3DProject/重构Chili/FreeCAD/src/Mod/Part/App/FaceMakerBuildFace.cpp::Build_Essence()`
- `/Users/admin/Chili3DProject/重构Chili/FreeCAD/src/Mod/Part/App/FaceMaker.cpp::postBuild()`
- `myShapesToReturn`
- `myPreSplitHistory`
- `mySplitter`

cad-core 目标流程：

```text
input wires / open split edges
  -> splitSelfIntersecting
  -> splitAtIntersections
  -> BOPAlgo_BuilderFace
  -> myShapesToReturn equivalent
  -> FaceMakerHistory
  -> InternalShape
```

### 整改动作

1. 把 `buildBoundedFacesFromEdgeNetwork()` 定为 FaceMakerBuildFace 主路径候选，而不是 fallback 后备。
2. 补 `FaceMakerBuildFaceRuntime`：
   - source edge list。
   - pre-split edge list。
   - splitter result edge list。
   - BuilderFace areas。
   - history mappings。
3. `makeFaceWithHolesFromClosedWiresImpl()` 只保留给明确的 Cheese/Bullseye/Simple face maker 模式。
4. `connectedSplitEdgesFromBoundary()` 不能决定业务输入边集合；它最多作为 diagnostic 输出“哪些 open edges 与 boundary 连通”。
5. `topologyWasSplit()`、face count 比较不能再决定最终 topology 选择。

### 验收点

- FaceMakerBuildFace 输出能标注来自 BuilderFace 的 area / edge source。
- `FaceMakerHistorySummary` 从 count summary 升级为可消费的 history ledger。
- overlapping closed wires、hole/island、T-junction open splitter 分别有专门 fixture。

## 偏移 5：Sketch InternalShape ElementMap/history 几何合成

### 当前流程

当前 `namedShapeForSketchInternalShape()` 里会调用：

```text
internalElementMapForSketch(rawShape, internalShape)
internalGeneratedFaceHistoryForSketch(rawShape, internalShape)
internalSplitElementHistoryForSketch(rawShape, internalShape)
internalDeletedElementHistoryForSketch(rawShape, internalShape)
```

这些 helper 通过 edge endpoint、curve sampling、outer wire source、raw/internal shape 对比，生成 `ElementMap` alias 和 split/generated/deleted history。

### 为什么偏了

这类 helper 原本适合用来说明“现在缺少 MapperHistory 时，几何上看起来发生了什么”。但它现在写入 `NamedShape.history`，会影响：

- stable subname resolve；
- `element_map_status`；
- ExternalGeometry；
- Pad/Profile stable reference；
- 后续 `PropertyLinkSub` 更新诊断。

它已经不是诊断，而是拓扑命名主路径。

### 正确主路径

FreeCAD 依据：

- `/Users/admin/Chili3DProject/重构Chili/FreeCAD/src/Mod/Sketcher/App/SketchObject.cpp::getInternalElementMap()`
- `/Users/admin/Chili3DProject/重构Chili/FreeCAD/src/Mod/Part/App/FaceMaker.cpp::postBuild()`
- `/Users/admin/Chili3DProject/重构Chili/FreeCAD/src/Mod/Part/App/TopoShapeExpansion.cpp::makeShapeWithElementMap()`
- `/Users/admin/Chili3DProject/重构Chili/FreeCAD/src/Mod/Part/App/TopoShapeMapper.cpp::MapperHistory`

cad-core 目标流程：

```text
FaceMaker / WireJoiner runtime history
  -> topo::MapperHistory equivalent
  -> ElementMap update
  -> NamedShape history/status
  -> stable subname resolution
```

### 整改动作

1. 将几何合成 helper 分为两类：
   - `internalElementMapForSketch()`：只保留 FreeCAD `getInternalElementMap()` 明确支持的 exact single result edge/vertex mapping。
   - `internal*HistoryForSketch()`：从主路径移除，改成 diagnostic probe。

2. 新增正式输入：
   - `SketchInternalHistoryContext` 不再只存 count 和 boolean。
   - 增加 source edge id、preSplit id、splitter result id、WireJoiner EdgeInfo id 到 Internal* name 的映射。

3. `namedShapeForSketchInternalShape()` 改为：

   ```text
   addIndexedElements()
   -> consume exact internal element map
   -> consume FaceMaker history
   -> consume WireJoiner history
   -> expose unresolved split/deleted diagnostics
   ```

4. 删除从 raw/internal shape 采样推 `Generated/Split/Deleted` 的主路径写入。

### 验收点

- 一对多 split 不再靠 `samplesLieOnEdge()` 认定。
- generated InternalFace 的 source 不再靠 outer wire sample 推断，而来自 FaceMaker history。
- deleted raw Edge/Vertex 不再靠“不存在于 internal shape”判断，而来自 MapperHistory/ElementMap terminal state。

## 偏移 6：ReferenceShadow 恢复通道边界

### 当前流程

`ReferenceShadow` 当前用于：

- `feature_extrude.cpp` 中恢复 Pad/Pocket Profile 的 InternalFace；
- `sketch_object.cpp` 中恢复 ExternalGeometry 的 InternalEdge/InternalVertex；
- `topo/reference_matcher.*` 中通过 fingerprint 或 BREP snapshot 找唯一 subshape。

### 为什么需要单独处理

这不是普通错误 fallback。仓库规则已经批准 `ReferenceShadow.brep` 是唯一可以保存的单 subshape 旧几何快照，用作无状态引用恢复证据。

但它仍然有偏移风险：如果把它扩展成完整 BREP cache、建模输入、通用拓扑命名推断，就会破坏 CAD Core 无状态边界。

### 正确边界

允许：

- 只保存被引用的单个旧 subshape snapshot。
- 只用于引用恢复证据。
- 必须校验 target id、property、shape type、fingerprint / sha256 / byteLength。
- 只能在 `ElementMap` 无法恢复时作为 fallback。

禁止：

- 保存完整对象 BREP 作为建模输入。
- 用 ReferenceShadow 替代 FaceMaker/WireJoiner/MapperHistory。
- 用 BREP 匹配结果生成新的稳定命名规则。
- 在 response 中把 BREP 当长期几何状态输出。

### 整改动作

1. 给 ReferenceShadow 恢复路径增加统一封装，例如 `topo::recoverReferenceShadowSubshape()`。
2. 所有调用点必须先尝试 `NamedShape` / `ElementMap`，再进入 ReferenceShadow。
3. 恢复成功时输出明确 metadata：

   ```text
   reference_recovery = "reference_shadow_single_subshape"
   reference_recovery_reason = "element_map_missing_or_split"
   ```

4. 如果 `ElementMap` 已经能稳定恢复，不再走 ReferenceShadow。

### 验收点

- 单 subshape drift 能恢复。
- split / ambiguous / deleted 能明确诊断。
- 不出现完整 BREP 输入建模路径。

## 实施阶段

### 阶段 0：冻结新增形态规则

目标：防止偏移继续扩大。

动作：

- 禁止新增 boundary、endpoint、partial overlap、face count、fixture shape name 类规则进入主路径。
- 当前可疑 helper 加注释标记“临时偏移点，待本方案删除”。
- 给新增测试区分 `diagnostic_probe` 与正式 result。

验收：

- `rg "boundary-touch|partial|cycle|same-coordinate|topologyWasSplit|samplesLieOnEdge" cad-core/src/geometry cad-core/src/topo` 的命中必须能说明是诊断、低层几何工具或已登记偏移点。

### 阶段 1：WireJoiner final ownership 主路径

目标：先解决最严重的主路径偏移。

动作：

1. 迁移 `EdgeInfo` live list identity。
2. 迁移 `WireInfo` ordered vertices。
3. 迁移 `findTightBound()` owner 写入。
4. 迁移 `exhaustTightBound()` secondary owner。
5. `getOpenWires()` 只消费 final fields。
6. 删除 `classifyBoundedFaceOwnership()` 对 export state 的写入。
7. 删除 `copiedResultWireGraphForSketchInternals()` 主路径。

验收：

- open export 条件只剩 FreeCAD final fields。
- 现有 P5 internal face fixture 不允许新增 known-mismatch 特判。
- trace 能展示 source edge -> split edge -> final owner -> open export。

### 阶段 2：FaceMakerBuildFace runtime/history

目标：让 FaceMaker 主路径提供可消费 history。

动作：

1. 建 `FaceMakerBuildFaceRuntime`。
2. `buildBoundedFacesFromEdgeNetwork()` 输出 edge/face history，不只输出 shape。
3. 区分 BuildFace、Cheese、Bullseye、Simple 模式。
4. 删除 face count/topology split 选择逻辑。

验收：

- `FaceMakerHistorySummary` 升级为 history ledger。
- InternalFace generated source 来自 FaceMaker history。
- overlapping/hole/island/T-junction case 均可解释。

### 阶段 3：Topo history 消费改造

目标：`topo/` 不再从几何结果发明历史。

动作：

1. `namedShapeForSketchInternalShape()` 改为消费 history context。
2. `internalGeneratedFaceHistoryForSketch()` 从主路径移除。
3. `internalSplitElementHistoryForSketch()` 从主路径移除。
4. `internalDeletedElementHistoryForSketch()` 从主路径移除。
5. 保留 `internalElementMapForSketch()` 的 exact edge/vertex single-result mapping。

验收：

- `NamedShape.history` 每一条 generated/split/deleted 都能追溯到 FaceMaker/WireJoiner/MapperHistory。
- stable subname split/deleted 诊断不再依赖 raw/internal shape 几何采样。

### 阶段 4：ReferenceShadow 收窄

目标：把批准例外保持在边界内。

动作：

1. 抽统一恢复函数。
2. 所有 Profile / ExternalGeometry 路径先走 ElementMap。
3. 恢复 metadata 标明 ReferenceShadow。
4. 增加完整 BREP 输入禁止项测试或 schema 约束。

验收：

- ReferenceShadow 只在 ElementMap 无法恢复时使用。
- 成功/失败/ambiguous/deleted 都有结构化诊断。

2. `SketchInternalBuildResult.internalShape` 不再通过 copied result-wire graph 从 bounded face 结果补边。
3. `FaceMakerBuildFace` 的 result/history 来自主路径 runtime，而不是 face count/topology switch。
4. `NamedShape` 的 generated/split/deleted history 不再由 raw/internal shape 几何采样合成。
5. `ReferenceShadow` 只作为单 subshape 引用恢复证据，并且所有调用点都有 ElementMap-first 顺序。
6. fixture 通过之外，还能用 trace 说明 final ownership 与 history 如何进入 `NamedShape` / `ElementMap`。
