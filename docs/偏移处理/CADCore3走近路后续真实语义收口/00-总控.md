# CADCore3 走近路后续真实语义收口总控方案

## 1. 目的

`docs/偏移处理/06-06-04-29-CADCore3走近路问题整改方案.md` 已经把当前 CADCore3 的能力状态、短期实现边界和 WireJoiner helper bridge 口径整理清楚。这个目录只承接后续真实语义收口，不再重复前一份文档里的已实现整改项。

本目录拆成一个总控方案和三个独立子方案：

- `01-真实OndselSolver迁移方案.md`：把 Assembly 从 representative solver / transport contract 推进到真实 Ondsel 约束求解。
- `02-CopyOnChange完整DeepCopyLifecycle迁移方案.md`：把 Link CopyOnChange 从 writeback contract 推进到完整 deep copy 生命周期。
- `03-WireJoinerBridge彻底删除方案.md`：用 FreeCAD WireJoiner 内部账本替换 generated open export / purge helper bridge。

不纳入本目录范围：

- GCS / Sketch solver。它和 Assembly/Ondsel 求解器不是同一条调用链，应另起方案。
- taper / draft 的通用 local history 迁移。它是 PartDesign 特征历史链问题，应另起方案。
- 重新证明 `06-06-04-29-CADCore3走近路问题整改方案.md` 的已实现状态。该文档只作为当前基线。

## 3. 为什么必须拆三份方案

这三项不是同一种工程问题：

- Assembly/Ondsel 是外部求解器 adapter、joint DTO、placement validation 和 writeback 问题。
- CopyOnChange 是 App 层对象复制、属性树复制、链接重定向、依赖图和历史保留问题。
- WireJoiner bridge 是 Part/WireJoiner 内部账本、open wire ownership、history mapper 和 internal element 命名传播问题。

如果混成一份大方案，验收时很容易出现“transport 已通就算 covered_full”或“fixture parity 过了就默认桥已删除”的口径错误。因此三份方案必须独立推进、独立验收、独立更新 gap 表。

## 4. 共同约束

- 先读 FreeCAD 调用链，再写 CAD Core 实现。每个子方案开工前必须补齐对应 FreeCAD 源文件、类/函数、关键字段和调用顺序。
- 不从 fixture 输出倒推业务逻辑。不得新增按 fixture 名称、几何类型组合、source/split 形态或导出顺序的补丁逻辑。
- 保持 CAD Core 无状态边界。请求里的 `DocumentObject graph` 是唯一真实数据，backend 不保存跨请求求解器 session、shape cache 或 copy cache。
- capability status 必须区分 contract / representative / bridge / covered_full。只有真实 FreeCAD 语义链迁完并通过对应验收，才能改成 `covered_full`。
- 如果短期保留 fallback，只能保留为明确的临时兼容路径，并写清删除条件；不得在 fallback 上继续叠加新 helper reason。
- 文档和代码落点要按 FreeCAD 模块语义归位：Assembly 到 `assembly`，CopyOnChange 到 `app` / `document`，WireJoiner 账本到 `part` / `topo`，不要塞进 adapter 或 sketch executor。

## 5. 推荐实施顺序

1. 先做 CopyOnChange lifecycle。它主要在 App / Link / Document graph 边界内收口，外部依赖少，能先把 CADCore3 capability 表里的 Link 口径改干净。
2. 再做 Assembly/Ondsel solver。它需要 solver adapter、joint matrix、placement validation 和失败诊断，范围较大，适合单独阶段推进。
3. WireJoiner bridge 可以作为独立 topology track 并行，但不要和前两项混在一个 PR 或一个验收口径里。它回归风险最高，应保留专门的 P5/P6/internal-face fixture 验收。

如果当前 blocker 明确来自 WireJoiner internal face / open wire ownership，可以优先启动 `03`，但仍然必须按独立账本迁移方案推进。
