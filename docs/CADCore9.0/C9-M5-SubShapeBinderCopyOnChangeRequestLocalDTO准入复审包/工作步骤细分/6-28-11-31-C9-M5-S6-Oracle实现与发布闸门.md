根据 S3-S5 证据完成 C9-M5 release gate。S6 只消费已经明确的 `backend_gap_requires_implementation`、`known_gap_retained`、`needs_more_native_evidence` 或 `release_gate` row，不新增业务范围。

## 入场条件

- S0-S5 均已按验收通过并重命名为 `【已实现】`。
- `c9m5_copyonchange_scope_review_matrix.tsv` 中每个 scope 都有最终 route。
- `c9m5_copyonchange_backend_gap_classification.tsv` 明确说明是否存在 `backend_gap_requires_implementation`。
- S4 产品裁决和 S5 implementation gate 一致。

## 本轮代码实现目标

只有存在 `backend_gap_requires_implementation` 时，S6 才允许落代码。

| blocker / scope | C++ 落点 | FreeCAD authority | 测试 | 成功标准 |
| --- | --- | --- | --- | --- |
| `C9M5-BLOCKER-601` / `C9M5-SCOPE-201` | `cad-core/src/part_design/feature_shape_binder.cpp` | `SubShapeBinder::setupCopyOnChange()`、`SubShapeBinder::update()` | `cad-core/tests/test_c8_shapebinder.py` 或新增 `tests/test_c9_copyonchange.py` | DTO-backed CopyOnChange 子集 request-local parity，且不保存 hidden cache。 |
| `C9M5-BLOCKER-601` / `C9M5-SCOPE-201` | `cad-core/src/app/copy_on_change.cpp` | `LinkBaseExtension::syncCopyOnChange()`、`makeCopyOnChange()` | focused document update tests | documentObjectUpdates / property delta 与 DTO 一致。 |
| `C9M5-BLOCKER-601` / `C9M5-SCOPE-202` | `cad-core/src/runtime/capability_contract.cpp` | current capability known gap block | `cad-core/tests/test_adapters.py` | 删除或收窄 remaining gap 只发生在 fixture / tests / DTO evidence 同步通过后。 |

禁止路径：

- 不按 fixture 名、bbox、面积、长度、几何类型或输出排序猜 CopyOnChange。
- 不在 adapter/output JSON 末端补业务逻辑。
- 不保存跨请求 FreeCAD document、temporary document、BREP、TopoDS_Shape、NamedShape、ElementMap 或 copied-object cache。
- 不把 `_CopiedObjs`、native object pointer identity 或 hidden document name 作为前后端合同。

## no-code release gate

若 S5 没有 `backend_gap_requires_implementation`，S6 必须关闭为 no-code release gate：

- 保持 `copy_on_change_full_temporary_document_cache` 为 `known_gap_diagnostic` / `oracle_blocked`。
- 更新 README、总入口、方案、步骤索引和矩阵，记录 S3-S5 证据。
- 保持 `delete_condition`：只有 FreeCADCmd / native probe 暴露稳定 request-local CopyOnChange copied-object evidence 且产品批准 DTO 后才替换。
- 保持 `reopen_condition`：只有更强 native oracle 或明确产品决策才能重开。
