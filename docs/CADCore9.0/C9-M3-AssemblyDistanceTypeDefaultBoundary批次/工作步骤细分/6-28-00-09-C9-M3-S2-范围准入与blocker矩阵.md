# C9-M3 S2 范围准入与 blocker 矩阵

## 目标

把 S1 的 source candidates 路由成可执行 scope：哪些是已有 expected 可直接复审，哪些需要 native oracle 批量采集，哪些保持 non-goal，哪些只到 S6 release gate。

## 分类规则

| route | 含义 |
| --- | --- |
| `baseline_closed` | 只证明 live state 和声明口径。 |
| `existing_expected_review` | checked-in expected 已存在，下一步比较 native expected 与 current behavior。 |
| `native_oracle_required` | FreeCAD source 明确但 expected 不完整，下一步必须采集 native expected。 |
| `diagnostics_guard_review` | 现有 unsupported diagnostics 需要在实现后继续可见。 |
| `release_gate` | capability / docs / queue / tests 发布闸门。 |
| `diagnostic_non_goal` | 当前产品边界外，不进入 C9-M3 代码实现。 |

## 必须回写的矩阵行

- `C9M3-SCOPE-101..404`
- `C9M3-BLOCKER-201`
- `C9M3-BG-101..601`
- `C9M3-NG-001..005`

```bash
awk -F '\t' 'FNR==1{n=NF; next} NF!=n{print FILENAME ":" FNR ": expected " n " fields, got " NF; bad=1} END{exit bad}' docs/CADCore9.0/C9-M3-AssemblyDistanceTypeDefaultBoundary批次/矩阵/*.tsv
git diff --check
```

## 验收标准

- 每个 scope 都有 source candidate、owner step、cad-core landing 和 close condition。
- 每个 blocker / backend gap / non-goal row 都能回链到 scope。
- 没有 native expected 或 current mismatch 的行不能被写成 `backendGap`。
- 缺 expected 的 default branch 组合只能进入 `native_oracle_required` 或 `notCollected`，不能继承 `PlaneCone` 的结论。

## 非目标

- 不在 S2 改源码或 fixture。
- 不把 release gate 当作代码实现证据。
- 不把 `default_or_todo_branch_support` 直接删除。
