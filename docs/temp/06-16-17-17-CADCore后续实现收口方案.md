# CAD Core 后续实现收口方案

## 当前基线

`cad-core` 已经不是空壳，当前源码已形成独立 C++17 / CMake Core，覆盖 document graph 解析、依赖图、recompute runtime、Sketcher、Part、PartDesign、TopoNaming、Link、Assembly display / solver adapter、CLI / C ABI / Worker / WASM adapter 等主要框架。

本次盘点得到的可见状态：

- `cad-core/src/runtime/feature_registry.cpp` 当前注册约 65 个 `TypeId` executor。
- fixture 总量约 497 个，其中约 286 个带 FreeCAD expected。
- expected 中仍有 9 个 `known_gap`，集中在 P7 Hole 线程孔 / 标准孔 oracle pending 类用例。
- `cad-core/src/adapters/c_api/c_api.cpp` 的 capability 输出里，多个早期 `remaining_gaps` 已清空，顶层 `known_gaps` 也声明为空。
- `docs/CADCore方案` 中部分“未完成边界”已经落后于当前源码能力声明，需要刷新，不能再只按旧文档判断剩余实现量。

当前本机验证阻塞：

- `cad-core/build/` 不存在。
- 执行 `cmake -S . -B build` 时失败，原因是 `nlohmann/json.hpp was not found`。
- 因此当前无法在本机跑 `python3 -m unittest tests/test_mvp.py` 得到真实测试结论。这个问题属于验证环境缺依赖，不等价于 CAD Core 源码实现失败。

## 目标状态

短期目标不是继续盲目补功能，而是先把实现状态、测试基线和剩余缺口对齐：

1. 本机能稳定配置、构建并运行 `cad-core` 测试。
2. 用实际测试结果替代过期文档判断，得到真实失败列表。
3. 把剩余实现按 FreeCAD 语义来源、cad-core 落点、fixture / oracle 验收拆清楚。
4. 更新 `docs/CADCore方案` 的阶段状态，使其与 `c_api.cpp` capability、fixture expected 和测试断言一致。
5. 后续任何 CAD Core 排查、实现方案、收口计划，先落到 `docs/temp`，确认后再并入正式方案目录。

## 后续实施顺序

### 第一步：恢复本机验证环境

先解决 `nlohmann/json.hpp` 缺失。可选路径：

- 或者在不破坏上游边界的前提下，确认项目是否已有 vendored json 入口，再调整 CMake 查找路径。

本步不改 CAD Core 业务逻辑。


### 第三步：刷新状态文档

对齐以下来源：

- `docs/CADCore方案/00-CAD-Core抽取方案.md`
- `docs/CADCore方案/细化方案/00-CAD-Core完整抽取执行总览.md`

刷新原则：

- 已被源码 capability 和测试断言标成完成的能力，不继续写成主缺口。
- 仍只有 summary / first slice / request-local boundary 的能力，要写清当前边界，不夸大成完整 FreeCAD parity。
- `known_gap`、oracle pending、diagnostic-only、unsupported matrix 要分开记录。
- 文档只记录基线、结论、剩余风险和验收命令，不记录流水账。

### 第四步：收口 Hole 线程孔 oracle pending

当前 expected 中可见 9 个 `known_gap` 都是 P7 Hole 线程孔 / 标准孔 oracle pending：

- threaded standard counterbore / countersink
- dynamic fastener data
- thread depth
- custom / class clearance
- model thread metric

实施路径：

1. 复核 FreeCAD `src/Mod/PartDesign/App/FeatureHole.cpp` 中 `Hole::readCutDefinitions()`、`Hole::makeThread()`、`Hole::findHoles()`、头部尺寸和 thread profile 相关路径。
2. 在本机非 sandbox 环境用 `FreeCADCmd` 重新采集 oracle。
3. 冻结 bbox、volume、topology counts、NamedShape / ElementMap expected。
4. 如果 cad-core 输出不一致，再按 FeatureHole / topology history 语义修实现。
5. 删除 expected 中对应 `known_gap`。

### 第五步：用失败列表驱动实现

如果测试暴露真实实现缺口，按模块落点处理：

- `document/`：只处理 DocumentObject graph、typed property、PropertyLink / XLink / LinkSub / ReferenceShadow 解析。
- `graph/`：只处理依赖、目标选择、循环和缺失链接诊断。
- `runtime/`：只处理 registry、recompute、reference resolver、updates 和 diagnostics。
- `sketcher/`：表达 SketchObject、约束、ExternalGeometry 状态机和调用顺序。
- `part/`：承接 OCCT shape、FaceMaker、WireJoiner、ShapeFix、TopoShape、PropertyTopoShape、Part Boolean / Offset / Import / Export。
- `part_design/`：承接 Body、Pad、Pocket、Hole、DressUp、Pattern、Transform、Datum。
- `assembly/`：承接 Assembly object、JointGroup、solver adapter 和 placement writeback。
- `adapters/`：只做 CLI / C ABI / Worker / WASM 协议转换，不写业务补丁。

不得用 fixture 名称、几何类型排序、输出端修剪或 source edge 猜测替代 FreeCAD 通用账本。
