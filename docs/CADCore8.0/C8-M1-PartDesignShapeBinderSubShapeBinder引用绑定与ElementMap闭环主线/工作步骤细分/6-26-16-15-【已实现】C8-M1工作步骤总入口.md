## 执行顺序

1. 每一步开始前先执行 live baseline：`pwd`、`git rev-parse --short HEAD`、`git log -1 --oneline`、`git status --short -uall`。
2. 每一步先运行本目录 `step_goal_queue.py`，只处理当前第一个 pending 文件。
3. S0/S1/S2 只允许文档和矩阵，不新增 fixtures/expected/tests，不改 C++。
4. S3 可以新增 oracle collector / fixture / expected / known_gap evidence，但不能改 runtime C++ 主路径。
5. S4 只有在 S3 产出 source-backed expected 且 current `cad-core` 缺失或 mismatch 时才改 C++。
6. S5 发布 tests / capability / docs；S6 只做 release gate。

## 状态纪律

- 不把 `backend_gap_candidate` 写成 `backend_gap_requires_implementation`，除非 S3 expected 和 current mismatch 都成立；S3 已对 Binder executor / ElementMap / BindMode 子集满足该条件。
- 不把 CopyOnChange / Frozen / Detached 直接写成 supported，除非能 request-local 化并有 native expected。
- 不把 `oracle_candidate` 或 `backend_gap_candidate` 当作 supported 发布结论。
- 不因单个 ShapeBinder fixture 通过就关闭 SubShapeBinder、ElementMap 或 lifecycle rows。
- 不从 current `cad-core` 输出倒推 FreeCAD expected。
- 不在 adapter/output 层增加业务补丁。
