# CAD Core 3.0 总览

## 目标

CAD Core 3.0 的目标是建立 FreeCAD 几何库复刻版的长期主线：用本地 FreeCAD 源码定义语义，用 `cad-core` 承载无状态几何计算，用 expected fixture / oracle / diagnostics 固定行为边界。

3.0 仍然不复刻 FreeCAD GUI、Workbench、ViewProvider、TaskPanel 或跨请求后端会话。它复刻的是前端长期编辑所需的几何建模核心语义：DocumentObject graph、属性链接、Sketcher、Part、PartDesign、TopoNaming、Link、Assembly 和 adapter contract。

## 当前基线

CAD Core 3.0 当前已经从“路线图展开”进入“冻结后收口”状态。C3-M1 到 C3-M7 的大类能力已经落到当前 capability、fixture 和 diagnostics 中；不再保留 CAD Core 2.0 遗留的笼统 `known_gaps`。

| 分组 | 当前状态 | 边界 |
| --- | --- | --- |
| `app / graph / runtime` | FreeCAD 风格 `DocumentObject graph`、属性链接、recompute 目标、结构化 diagnostics 和 request-local update channel 成立 | 后端仍无跨请求 document session；前端 graph 是唯一持久状态 |
| `topo_history` | `MapperHistory` core、producer matrix、ElementMap policy、child-map source range、ShapeFix / import / offset / section / DressUp / transformed / Hole / Loft ThruSections / Sweep PipeShell / Filling、WireJoiner full ledger 等 maker history 已有 fixture 或 diagnostics | `topo_history.remaining_gaps` 当前为空 |
| `sketcher` | solver diagnostics、request-local 几何写回、ExternalGeometry Frozen / Detached / Missing 生命周期、Sketch InternalShape producer evidence、WireJoiner open-export / noOriginal mapper history 已有覆盖 | full ledger 只表示当前内部面 / history / ElementMap 主路径，不表示 GCS solver 完整复刻 |
| `part / part_design` | Part Offset / Offset2D / Thickness / Section、source-backed Part::RuledSurface / Part::ProjectOnSurface / Part::Loft profile / Linearize、Part::Sweep multi-profile / Linearize、Part::FilledFace helper / Part::GeomPlateSurface helper 第二批、Body chain、DressUp、transformed / pattern、Hole table / ModelThread / head-cut native oracle 已有代表路径 | Part surface 只发布 verified slices；ProjectOnSurface projected edge provenance mapper/history、GUI task panel、未验证高级分支、Loft `complex_profile_family`（`future_loft_complex_profile_family`）、Sweep advanced PipeShell contract（`future_sweep_advanced_contract`）、Filling support/order/constraint/param family、GeomPlate G1 native oracle、ProjectedCurve2d native oracle、curve criteria setter `NotImplementedError`、`Part.PlateSurface.Curves` wrapper lifecycle 仍需独立 owner；完整 Part surface family 保持 non-goal |
| `link / assembly` | Link transaction、CopyOnChange deep copy、reference lifecycle、Assembly Ondsel grounded JointType、placement writeback 已收口 | representative solver 只代表 fallback，不作为 full solver 依据 |
| `adapters / object_metadata` | CLI / C ABI / Worker / WASM / streaming mesh / binary mesh 复用同一 core；Pad / Pocket / Part::Extrusion taper metadata 为 `covered_full` | adapter 只做协议转换，不承载建模语义 |

WireJoiner full ledger 已完成当前收口：`cad-core/src/adapters/c_api/c_api.cpp::capabilitiesJson()` 把 `wire_joiner.generated_open_export_bridge` 与 `wire_joiner.purge_as_original_bridge` 标为 `covered_full`，remaining gaps 为空；open-export / noOriginal / split / deleted 关系由正式 `MapperHistory(aHistory) -> ElementMap` 消费。

后续收口不再追加过程记录。当前状态以 `06-C3-M8后续收口清单.md` 为冻结表，以 `07-【已实现】WireJoiner-MapperHistory接管方案.md` 为 WireJoiner 回归依据。

## 3.0 分阶段路线

| 阶段 | 主线 | 目标 |
| --- | --- | --- |
| C3-M0 | FreeCAD 语义矩阵 | 按 FreeCAD 模块建立复刻矩阵、gap 分级、oracle 队列和当前 capabilities 对照 |
| C3-M1 | TopoNaming 完全体 | 补 ShapeFix history、import shape ElementMap、full MapperHistory producer 生命周期 |
| C3-M2 | ExternalGeometry native 生命周期 | 旧 `ExternalGeo` 几何持久复用、Missing 可解析清理、Frozen / Missing `ReferenceShadow.brep` 单 subshape 快照复用、Detached link-list + native pool 写回、cross-document nested label writeback 与 external document pending/reload diagnostics 已有第一切片 |
| C3-M3 | Sketcher 复刻 | 补 solver-facing 约束语义、复杂 ExternalGeometry projection/intersection 和 sketch diagnostics |
| C3-M4 | Part Workbench 复刻 | 系统覆盖 Part primitive、Boolean、Extrude/Revolve/Sweep/Loft、Offset/Thickness、import/export history |
| C3-M5 | PartDesign 完整生态 | 补 full transformed / pattern history、DressUp 复杂参数、Body chain writeback、Hole 表驱动、Loft/Pipe/Revolution/Groove 等 family |
| C3-M6 | Link / Assembly 完整生命周期 | 补 `_ChildCache`、copy-on-change deep copy、document hash、Ondsel solver 和 placement write-back |
| C3-M7 | Runtime / adapter 产品化 | 补 Worker / WASM、streaming mesh、binary mesh、资源限制和前端错误码映射 |
| C3-M8 | FreeCAD parity freeze | 收敛 oracle、capabilities、known gaps、文档和回归门禁，形成 3.0 冻结基线 |

## 推荐推进顺序

1. 先做 C3-M0。没有模块矩阵，后续会继续靠局部 fixture 驱动，无法判断“复刻 FreeCAD 几何库”完成度。
2. 再做 C3-M1 / C3-M2。TopoNaming 与 ExternalGeometry 是所有长期引用恢复的底座。
3. 再做 C3-M3 / C3-M4 / C3-M5。Sketcher、Part、PartDesign 的 feature 扩展必须消费统一 history，而不是重新创建局部 mapper。
4. 最后做 C3-M6 / C3-M7。Link、Assembly、Web adapter 依赖前面的引用恢复和 maker history，否则容易把语义泄漏到前端或 adapter。
5. C3-M8 只做冻结，不新增大语义。

## 非目标

- 不实现 FreeCAD GUI / ViewProvider / Workbench / TaskPanel。
- 不把 BREP 作为前端或后端长期状态；唯一例外仍是 `ReferenceShadow.brep` 的旧单 subshape snapshot。
- 不维护跨请求后端 document session；前端的 `DocumentObject graph` 仍是唯一真实持久数据。
- 不用 fixture 名称、输出顺序、bbox、面积、几何类型排序、source edge 猜测来修正引用。
- 不把 Assembly solver、Worker / WASM 或 Web adapter 作为 TopoNaming 主线的前置条件。

## 3.0 完成判定

3.0 完成时应满足：

- FreeCAD 语义矩阵中的 P0 / P1 项均有源码依据、cad-core 落点、fixture / oracle 或明确 `known_gap`。
- ShapeFix、Refine、taper、transformed、DressUp、Part Boolean、import shape、Link retag 后的 source ownership 都进入统一 MapperHistory / ElementMap 生命周期。
- ExternalGeometry、ReferenceShadow、StableSubList、FullSubList、LinkSub、document hash 和 rename recovery 的成功 / 失败路径都有结构化更新或 diagnostics。
- Sketcher / Part / PartDesign 常用建模链可以在前端长期编辑后稳定 recompute。
- Assembly 至少有 stateless representative solver adapter 成功路径和 placement write-back；未支持 JointType 有稳定 diagnostics。
- CLI / C ABI / Worker / WASM / Web adapter 复用同一 core recompute，不承载业务语义。
