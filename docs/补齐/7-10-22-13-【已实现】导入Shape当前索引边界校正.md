# 导入 Shape 当前索引边界校正

## 当前边界

`Part::ImportBrep`、`Part::ImportStep` 与 `Part::ImportIges` 每次从 `FileName` 读入当前
`TopoShape`。它们发布 `FaceN` / `EdgeN` / `VertexN` 的当前索引，但没有因此产生
`ElementMap`、`MapperHistory` 或可跨 recompute 保存的 `stableSubname`。

因此，导入结果及其 `topoNamingState` 必须是 `indexed_only`：公开 subshape 的
`identityStatus` 为 `current_only`，`stableSubname` 为空，且 element-map、child-map 与
mapper-history 为空。客户端不能把对象限定的 `ImportedStep.Face1` 之类当前显示路径当作
stable token；只有后续真实 producer-side 映射证据或已验证的请求携带状态才可支持恢复。

## FreeCAD 依据

- `src/Mod/Part/App/FeaturePartImportBrep.cpp::ImportBrep::execute()` 与
  `FeaturePartImportStep.cpp::ImportStep::execute()` 仅调用 `aShape.import*()` 后
  `this->Shape.setValue(aShape)`。
- `src/Mod/Part/App/TopoShape.cpp::{importBrep,importStep,importIges}` 分别读入 shape；该链路
  不调用 `mapSubElement()`、`makeShapeWithElementMap()` 或 MapperHistory producer。
- `src/Mod/Part/App/PropertyTopoShape.cpp::PropertyPartShape::setValue()` 只传播已经存在的 map。
  c3m1 的同次 FreeCADCmd ledger 也记录空 `elementMap` / `childElementMaps` /
  `mapperHistory`。

## 发布与验证边界

`topo_history` capability 不再把导入声明成 mapper-history producer；`import_shape` 仅说明
STEP、BREP、IGES 的 native indexed-current-subshape 覆盖。历史实施包中关于
`import_shape_element_map` 或 owner-qualified import alias 的描述是旧实施快照，不是当前协议
权威。

导入 bbox 仍按 FreeCAD `TopoShapePy::optimalBoundingBox()` 的
`BRepBndLib::AddOptimal(shape, bounds, true, false)` 语义，在 CAD Core 生成显示 mesh 之前读取。
这会保留 BREP 文件自带 triangulation 的可见范围，同时不会把 CAD Core 新生成的 STEP/IGES
显示 triangulation 错当作输入 shape 的 native bbox。
