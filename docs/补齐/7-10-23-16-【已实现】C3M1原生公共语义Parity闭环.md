# C3M1 原生公共语义 Parity 闭环

## 范围与结论

本轮只关闭 c3m1 中具有成对 FreeCADCmd public expected 与 ledger 的三个 case：

- `element-map-child-map-recursive-compound`
- `part-import-brep-edge-stable`
- `part-import-step-face-stable`

三者均已由同一 CAD Core CLI live run 验证为 semantic green、`unaccepted=0`、
`geometry.numeric=0`，release gate 通过。phase 内其余九个没有 native expected 的 case 不在
本轮 parity 范围内。

## 根因、FreeCAD 调用链与实现落点

### 导入 Shape

FreeCAD 的
`src/Mod/Part/App/FeaturePartImportBrep.cpp::ImportBrep::execute()` 与
`src/Mod/Part/App/FeaturePartImportStep.cpp::ImportStep::execute()` 只执行
`TopoShape::import*()` 后 `Shape.setValue(aShape)`；
`src/Mod/Part/App/PropertyTopoShape.cpp::PropertyPartShape::setValue()` 只传播已存在的 map。
所以导入的 `FaceN` / `EdgeN` / `VertexN` 是当前索引，并不是 `ImportedStep.Face1` 一类稳定
token。旧 CAD Core 在 `part/topo_shape_expansion.cpp` 制造 owner alias 和 mapper history，且
删除引用时把它们当成真实身份，这是错误的 producer 语义。

现在 `part/topo_shape_expansion.cpp::namedShapeForImportedShape()` 只返回 indexed NamedShape；
`part/topo_shape.cpp` 也不再为该旧 alias 做 deleted 特判。`part/part_import.cpp` 统一走这条
边界，因此 public result 与 `topoNamingState` 均为 `indexed_only`：空 stableSubname、
`current_only`、空 ElementMap / child map / mapper history。

FreeCAD collector 的 bbox 在显示 mesh 前调用
`src/Mod/Part/App/TopoShapePyImp.cpp::TopoShapePy::optimalBoundingBox()`，其核心是
`BRepBndLib::AddOptimal(shape, bounds, true, false)`。`part/part_feature_support.cpp` 因而在
`meshForShape()` 前计算 bbox；BREP 保留文件携带 triangulation 的范围，STEP/IGES 不会把本轮
新生成的显示 triangulation 误写回 native bbox 语义。

### 递归 Compound

`src/Mod/Sketcher/App/SketchObject.cpp::convertSubName()` 生成 `g<ID>` / `g<ID>v<point>`，
`SketchObject::buildShape()` 再经 `makeElementWires(..., Part::OpCodes::Sketch)` 交给 Part。
随后 `src/App/ElementMap.cpp::ElementMap::addChildElements()` 明确要求“try to resolve the
grand child map now”，而
`src/Mod/Part/App/TopoShapeExpansion.cpp::{mapSubElement,createChildMap}` 负责把该账本沿
Compound child range 传播。

CAD Core 在 `sketcher/sketch_edge_identity.cpp` 记录 source-backed `g...;SKT...` 边和端点
producer 证据，并将其标为 `MappedNamePublicationScope::ProducerOnly`；
`part/topo_shape.cpp::recordInheritedMappedNameProvenance()` 只有在 Part maker 真正消费该
ElementMap 时才提升为 `Public`。同文件以 child owner 区分两个都叫 `g1` 的 Sketch，并只在
递归 Sketch 路径组合 parent tag。`NamedShapeChildMap::recursiveExpansion` 保留
request-local grandchild 解析范围。

canonical token 的多目标由 Part 的 `NamedShape::mapperHistory` 记录为 ambiguous 事件，再由
`runtime/topo_naming_state.cpp` 校验并投影；runtime 不从 C3M1 的 response/subshape DTO 反推或
新造该历史。它只发布 direct child map，并在缺少对应 Part ledger 时拒绝投影 Sketch collision
为 terminal ElementMap entry。C4M6 既有的 reference-driven stable-subname 兼容投影仍有独立
旧路径，但只在请求显式携带该类引用时启用，当前 C3M1 三个 case 不会进入它。

直接返回的 raw Sketch 不会把 `g...;SKT;:H` producer ledger 升格为 public state；只有下游
Compound 的 Part map 消费并提升 scope 后才可公开。这保持 `InternalShape` 与 raw Sketch
`Shape` 的边界，也避免 ReferenceShadow 等既有协议将 producer 账本误当作客户端 stable
identity。

## 回归与风险

```bash
cd ~/Chili3DProject/FreeCAD/cad-core
cmake -S . -B build -DCAD_CORE_OCCT_LIBRARY_ROOT=/Applications/FreeCAD.app/Contents/Resources
cmake --build build --target cad-core cad-core-c3m1-topology-probe -j4
python3 -m unittest tests.test_c3m1_native_public_parity
python3 -m unittest tests.test_topo_naming_state_response
python3 -m unittest \
  tests.test_p6_topology.CadCoreP6TopologyTest.test_c3m1_element_map_child_map_recurses_nested_compound_ranges \
  tests.test_p6_topology.CadCoreP6TopologyTest.test_c3m1_import_brep_keeps_imported_edges_current_only_without_mapper_evidence \
  tests.test_p6_topology.CadCoreP6TopologyTest.test_c3m1_import_step_keeps_imported_faces_current_only_without_mapper_evidence
python3 tools/compare_freecad_expected.py --phase c3m1 --write-current --bin build/cad-core
python3 tools/compare_freecad_expected.py --phase c3m1 --strict --output out/c3m1-snapshot.json
python3 tools/compare_freecad_expected.py --phase c3m1 --strict --live --bin build/cad-core --output out/c3m1-live.json
python3 tools/compare_freecad_expected.py --phase c3m1 --release-gate --run-contract-tests --bin build/cad-core --output out/c3m1-release-gate.json
```

最终报告为 3/3 ledger/preflight valid、current fresh；live release gate 为 true。允许差异为
既登记的 mesh product extension，以及 producer-local raw tag / collector 与 Part ledger 的
表示差异；均不是 geometry 或 topo semantic 差异。direct test 会逐个验证 raw tag 能投影到
同一 canonical token、candidate 顺序/端点精确一致，并明确断言两侧 provenance 标签，不会
通过排序或静默忽略 raw 字段掩盖差异。

`tests.test_p6_topology` 全量仍有既有失败：最终复跑
`python3 -m unittest tests.test_p6_topology tests.test_topo_naming_state_response` 为 57 个测试、
10 failures、13 errors。部分请求在 7 月 9 日 hash hard-fail 边界引入前生成，携带过期
`topoNamingState.documentHash`；另有缺少的 p3b native expected 与旧 topology 断言。它们不
属于本轮三个 C3M1 native case，也不能通过放宽 client-state hash 校验来掩盖。本轮改变的三个
C3M1 legacy P6 case 与完整 `tests.test_topo_naming_state_response` 已通过。
