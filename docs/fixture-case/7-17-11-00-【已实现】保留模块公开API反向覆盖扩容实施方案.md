## 1. 结论和目标

上一阶段已经闭合 fixture corpus 内的角色、FreeCADCmd public expected 和 ledger，但它只能证明“已登记能力的语料闭包”，不能证明保留模块全部历史 API 已覆盖。本方案的核心是先建立独立于现有 fixture 的公开 API 分母，再把每个 API/主要运行分支反向映射到由 FreeCADCmd 产生的 native fixture authority、native process authority，或有实际 FreeCADCmd 试探依据的非 native 例外。

本方案是 **FreeCADCmd 权威采集方案**，不是 CAD Core 实现或对比方案。全程不运行 CAD Core，不读取或生成 CAD Core 结果，不以 CAD Core 是否消费某个字段、是否已有 DTO、是否属于几何 runtime 来决定 FreeCAD 公开 API 是否采集。`cad-core/fixtures` 和 `cad-core/tools` 只是当前 authority 资产与采集工具的存放目录，不代表需要执行 CAD Core。

完成后必须同时能回答：

1. 剪枝后保留模块对外暴露了哪些类、属性、方法、命令和可执行分支。
2. 哪些能力有 native target/dependency/diagnostic 执行证据，哪些只有入口 smoke。
3. 哪些能力当前完全没有 fixture 表达。
4. 哪些能力应使用 document fixture，哪些应使用 FreeCADCmd process authority；只有实际依赖 GUI、真实网络或不可控宿主状态且无法由受控 FreeCADCmd 表达的分支，才能记录为非 native 例外。

本方案不以 fixture 数量、native 数量或一个模块有一条 case 作为全覆盖标准。

## 3. 第一道地基：建立独立的公开 API 分母

### 3.1 新增资产

新增：

```text
cad-core/tools/freecad_expected_parity/retained_public_api_surface.v1.json
cad-core/tools/freecad_expected_parity/reports/retained_public_api_coverage.v1.json
```

`retained_public_api_surface.v1.json` 不从 fixture 反推，而从剪枝后 target closure 和 FreeCAD 源码生成/维护。每条 API surface 至少包含：

```json
{
  "module": "Mesh",
  "symbol": "Mesh::SetOperations::execute",
  "publicSurface": "Mesh set-operation feature",
  "exposure": "DocumentObjectTypeId",
  "sourceEvidence": ["src/Mod/Mesh/App/FeatureMeshSetOperations.cpp::execute"],
  "runtimeBranches": ["union", "intersection", "difference", "invalid operation", "missing source"],
  "nativeExpressibility": "native_fixture|native_process_test|protocol_only|unsupported",
  "fixtureEvidence": [],
  "coverageStatus": "covered|thin|uncovered|non_native_exception"
}
```

### 3.2 分母来源

按以下来源取并集，不只扫描现有 fixture TypeId：

- `src/Main/MainCmd.cpp` 和 `src/Main/MainPy.cpp` 的进程/Python 入口、退出码和异常分支。
- `src/Base` 对 Python 暴露的 Console/Exception 方法。
- 每个保留 App module 的 `App*.cpp` 类型注册、`PROPERTY_SOURCE`/`ADD_PROPERTY`、`*Py.xml`、`*PyImp.cpp` 和 `.pyi`。
- `execute()`/`mustExecute()`/`onChanged()`/`onDocumentRestored()` 等公开运行分支。
- FreeCAD2 剪枝后 live target/runtime closure；已删模块不进入分母。

初版抽取可以是“候选符号 + 人工审核”，但报告必须 fail closed：新发现的符号没有 disposition 或 evidence 时，对应模块不得声称 API coverage passed。

### 3.3 证据等级

`fixtureEvidence.level` 固定为：

- `target_result`：目标对象实际执行并发布结果。
- `dependency_result`：依赖模块在主调用链中实际执行。
- `native_diagnostic`：FreeCAD 原生拒绝分支被结构化断言。
- `native_process_test`：FreeCADCmd/Base/MainPy 进程协议测试，不伪装成 document fixture。
- `entrypoint_smoke_only`：只经过入口，对应能力只能是 thin。

## 4. 实施批次与顺序

### A0：API 分母和审计门禁

目标：先让“源码存在但 corpus 从未表达”变成可见失败。

实施内容：

1. 生成候选 public surface，人工排除纯内部 helper、GUI-only 和已剪枝 target。
2. 为每条补 source evidence、runtime branch 和 native expressibility。
3. 扩展 `audit_freecad_fixture_authority.py`，联合 API surface、能力清单、phase registry、role 和 authority artifact。
4. 检查同一 fixture 映射多 API 时的 item-local evidence，禁止只因 TypeId/属性出现就判定主分支 covered。
5. 报告同时输出 `apiSurfaceClosure`、`moduleApiCoverage`、`fixtureCorpusClosure` 和 FreeCADCmd producer/authority closure；不输出、不引用其他运行时 parity 作为本方案门禁。

完成标准：所有保留模块都有源码侧 API 分母；无未分类符号；现有 57 条能力全部可追溯到 API surface，但不要求此时全部 covered。

### A1：Mesh primitives + set operations + defects

这是第一个实质扩容批次，原因是 FreeCAD 存在明确的 DocumentObject `execute()` 主链和可稳定观察的公开结果。

源码调用链：

```text
AppMesh.cpp 注册 Mesh feature TypeId
  -> FeatureMeshSolid.cpp::{Sphere, Ellipsoid, Cylinder, Cone, Torus, Cube}::execute
  -> MeshObject::create*
  -> Feature::Mesh

FeatureMeshSetOperations.cpp::SetOperations::mustExecute/execute
  -> Source1/Source2 + OperationType
  -> MeshCore::SetOperations::Do
  -> Feature::Mesh

FeatureMeshDefects.cpp::*::execute
  -> Source link
  -> MeshObject defect operation
  -> Feature::Mesh or native diagnostic
```

新 phase：

- `mesh-primitives`
- `mesh-setops`
- `mesh-defects`

最小完整语义集：

| 能力 | 正常 | 修改/recompute | 边界/失败 |
|---|---|---|---|
| primitive | sphere + cube 代表曲面/多面体 | radius/size/sampling 触发 `mustExecute()` | 0/负尺寸、最小 sampling |
| set operations | union/intersection/difference | 切换 `OperationType` 或修改 source | 缺 Source1/2、无效 operation、不相交 |
| defects | harmonize/flip + 一个实际修复 feature | 更换 source | 无 source、错误 property type、无可修复缺陷 |

collector 必须通用发布 mesh point/edge/facet count、bbox、closedness、volume 和必要的 defect summary；不得按 case 名分支。`Mesh::Transform::execute()` 主体被注释的边界继续保持 source-backed unsupported，不制造假几何。

### A2：Material card/library/model resolution

源码调用链：

```text
AppMaterial.cpp 注册 Material/Manager/Library Python surface
  -> MaterialManager::{getLibraries,getLibrary,libraryMaterials,getMaterial}
  -> MaterialLibrary / MaterialLoader / ModelLoader
  -> Materials::Material / PropertyMaterial
  -> Part::Feature.ShapeMaterial public projection
```

本能力通过 FreeCADCmd process authority 采集，不新增 document fixture phase；机器可读证据 ID 为 `process-contract/material-resolution`。

同批覆盖：

- 本地 card 正常解析和 UUID/name 定位。
- library/model 选择与 inheritance/override。
- card 修改后第二次 recompute。
- 缺失 card、未知 model/schema、无效属性类型和继承循环。

当前 document fixture 只暴露 material property map，但 card/library/model 引用仍属于需要采集的 FreeCAD 公开 API。能经 DocumentObject 表达的分支进入 native fixture；资源解析、cache、refresh 等非 document 调用进入受控 FreeCADCmd `native_process_test`。不得以其他运行时是否接收这些字段为判断条件，也不得只因 collector 尚未支持就写 unsupported。

### A3：Sketcher 高级几何与编辑操作

新 phase：`sketcher-operations`。不做一个巨大笛卡尔积，按调用链分为三个最小完整语义批次：

1. `SketchObjectOperations.cpp::trim/extend`：线、圆弧/圆锥曲线、不相交/退化边界。
2. `SketchObjectOperations.cpp::fillet`：trim/createCorner/chamfer 组合、半径修改、无效几何对。
3. clone/block/conic/B-spline 编辑：操作后 geometry/constraint/solver-facing 状态更新。

每批必须同时断言原始 geometry、constraints、solver-facing update 和 InternalShape/开轮廓必要证据。不在 `sketch_object.cpp` 里用几何类型特判凑结果。

### A4：Assembly/OndselSolver 支持矩阵

继续使用 `assembly-solve` phase，新增机器可读矩阵，不为每个笛卡尔组合手工写 fixture：

```text
joint type × marker geometry family × success/failure × placement writeback
```

源码链：`AssemblyObject::solve -> makeMbdAssembly -> marker/constraint creation -> Ondsel solve -> placement writeback/diagnostic`。

每个保留 joint type 至少覆盖：

- 一个支持的 marker 组合和真实 solve。
- 一个可观测 placement writeback。
- 一个退化/不支持 marker 组合。
- 一个欠约束、冲突或 solver 失败诊断。

完成条件是源码支持矩阵中每个等价类有证据，不要求无价值的全组合穷举。

### A5：FreeCADMainCmd / FreeCADBase / FreeCADMainPy 进程协议

这些能力不强塞进普通 document recompute expected。新增独立的受控工具和报告：

```text
cad-core/tools/collect_freecad_process_contract.py
cad-core/tools/freecad_expected_parity/reports/process_contract/*.json
```

覆盖：

- MainCmd 未知选项返回 1、ProgramInformation 返回 0、初始化 Base::Exception 返回 100 的可控分支。
- Console message/warning/error 格式和 observer/status 分支。
- `PyInit_FreeCAD` 模块初始化、重复 import 和确定性 shutdown。

测试必须固定 argv、环境白名单、exit code、stdout/stderr 规范化和 producer 身份。信号强杀、宿主嵌入等分支只有在受控 FreeCADCmd 无法安全、确定地触发时，才能依据实际试探回执保持 protocol-only/unsupported。

### A6：Spreadsheet layout FreeCADCmd authority 采集

源码链：

```text
SheetPy::{setStyle,mergeCells}
  -> Sheet::{setStyle,mergeCells}
  -> PropertySheet/Cell layout state
```

这些接口已经由 `SheetPyImp.cpp` 公开，并可通过 FreeCADCmd 调用 getter 观察结果，因此必须建立 native authority，不再做任何其他运行时边界决策：

- 新建 phase `spreadsheet-layout`，补 collector 的通用 operation 输入和 FreeCAD public projection。
- 同批覆盖 style、alignment、column width、row height、merge，修改 + unmerge，以及重叠/无效 range 的原生诊断。
- 每条正式 case 都由受控 FreeCADCmd 同次生成 `.freecad.json` 与 `.freecad.ledger.json`，完成 staging、repeat 2、promotion 和 checked-in repeat 2。
- 本批不运行 CAD Core，不生成 `cad-core-res`，也不要求任何 CAD Core DTO 或实现。

### A7：Help / AddonManager 功能边界审计

当前 import/path 和 metadata/SPDX smoke 只能证明“保留资产可加载”，绝不改写为功能覆盖。A7 必须逐 API 判断能否由受控 FreeCADCmd 或其同进程 Python module 入口稳定执行，而不是依据其他产品边界裁剪。

凡 FreeCADCmd 可表达的功能都建立 hermetic native process authority：

- Help：本地页面查询、缺失页面、路径规范化、外部 browser 失败。
- AddonManager：本地假仓库、mock network、临时用户目录中的发现/安装/升级/删除/版本冲突。

禁止访问真实网络或修改真实用户 Addon 目录。非 document API 不产生 `.freecad.json`/ledger，但必须产生带 FreeCADCmd producer 身份、repeat 2 和确定性结果的 process authority receipt，并计入对应 API 的权威覆盖。

## 5. 每个 native fixture 批次的固定交付物

每个 A1-A4/A6 native 批次必须一次闭合：

1. FreeCAD 源码绝对路径、类/函数、关键字段和调用顺序。
2. 对应 module/capability phase 的批量输入 fixture。
3. 通用 collector 输入/输出支持，无 case 名称特判。
4. 受控 FreeCADCmd 同次生成的 public expected + ledger。
5. staging 首采、staging repeat 2、promotion 和 checked-in repeat 2 回执。
6. focused collector/audit/semantic tests 和对应 coverage report 更新。
7. 只有受控 FreeCADCmd 实际试探证明无法 native 表达的 case 才能进入 protocol-only/unsupported，并附 source evidence、完整试探回执、next action 和 close condition；其他运行时不消费不是例外理由。

最小完整语义批次默认至少包含：正常执行、修改/recompute、边界或原生失败。不允许一个 phase 只增一条点名 fixture 就宣称能力完成。

## 6. 不同覆盖结论的门禁

### 6.1 fixture corpus closure

要求 input/role/native expected/ledger 严格闭合，以及 repeat 2 无运行间差异。它只证明语料资产完整。

### 6.2 API surface closure

要求剪枝后公开符号都有 disposition，无未分类新 API。它只证明分母完整，不代表全部 covered。

### 6.3 module API coverage

只有一个模块分母内每条 API/主要分支均为 covered 或 source-backed non-native exception，且没有 thin/uncovered，该模块才可以报 `passed`。全局只能在所有保留模块都满足后报 API coverage passed。

### 6.4 本方案不运行其他 runtime

本方案的唯一运行 producer 是 FreeCADCmd。验收不包含 CAD Core 或任何其他 runtime 的执行、输出、比较与 parity；后续若需要消费这些 authority，必须另立实施方案。

真正受阻只能是：FreeCAD 源码调用链不存在，或受控 FreeCADCmd 经实际试探仍无法安全、确定地表达。受阻时必须保留可复现输入、FreeCAD 源码依据、完整 FreeCADCmd argv/env/stdout/stderr/exit 或 signal、实际错误和下一批范围；不得用其他运行时的产品边界代替试探，也不得停在只完成盘点或只补一条 fixture。

## 9. 主要风险

- **分母虚高**：将纯内部 helper 当成 public API。通过 exposure 类型、注册点和人工审核排除。
- **分母虚低**：只扫描已有 fixture TypeId。必须从模块注册、Python wrapper 和 public header 反向建表。
- **属性命中冒充执行覆盖**：只有 `target_result`/`dependency_result`/`native_diagnostic` 才可使主分支 covered。
- **collector 演变成 fixture 解释器**：输入和投影按 TypeId/公开属性通用实现，不按 phase/case 名称分支。
- **用其他运行时边界缩小 authority**：FreeCADCmd 可调用的 Spreadsheet、文件或非几何 API 都要采集，不能因为下游暂不消费而标成例外。
- **误跑非 authority runtime**：本方案的命令和回执只能运行 FreeCADCmd；不得生成或引用 CAD Core 输出充当验收证据。

## 10. 推荐立即开始的实施范围

第一个 goal 应一次完成 A0 + A1，而不是只新增一条 Mesh fixture：

1. 签入保留模块 API surface v1 和 fail-closed 审计。

3. 新建 `mesh-primitives`/`mesh-setops`/`mesh-defects` 最小完整批次。
4. 补 collector 的通用 Mesh feature 输入和 public 结果投影。
5. 批量生成 expected/ledger，完成 staging + repeat 2 + promotion + checked-in repeat 2。
6. 更新 API/capability/module 三层报告，只声明 FreeCADCmd authority 覆盖。

该批次闭合后再进入 A2 Material，可以避免新 API 继续在无独立分母的情况下通过手工 capability 条目被遗漏。
