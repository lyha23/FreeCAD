## 目标

消费 S3-S5 的 `notCollected`、`backend_gap_candidate`、`no_gap`、`diagnostic_retained` 和 `releaseGate`。S6 是唯一允许改 C++ / fixtures / tests / capability 的步骤，但只有在 S4 产生 evidence-backed backend gap 时才打开实现。

## 输入

- S3 native oracle 结果。
- S4 parity comparison 结论。
- S5 non-goal / protocol boundary 结论。
- `c11m1_part_sweep_location_overload_blocker_queue.tsv`
- `c11m1_part_sweep_location_overload_backend_gap_classification.tsv`

## 实现顺序

1. 若 S3 仍 `notCollected`：关闭 `C11M1-BLOCKER-301/302` 为 retained evidence，`C11M1-BLOCKER-601` 发布 no-code retained non-parity gate。
2. 若 S3 stable 且 S4 `no_gap`：只更新 docs / capability wording / tests expectation，保留 c5m10 historical guard。
3. 若 S4 产生 `backend_gap_candidate`：先补 fixture / expected / focused test，再改 `part_sweep` / `topo_shape_expansion`，最后更新 capability 和 adapter tests。
4. 完成后运行本轮 focused validation；只有修改 core C++ / fixtures / capability 时才运行 cad-core build 和 focused unittest。
