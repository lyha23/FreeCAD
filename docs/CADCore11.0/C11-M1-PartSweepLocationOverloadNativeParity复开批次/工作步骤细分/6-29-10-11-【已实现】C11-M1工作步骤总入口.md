## 执行顺序

1. 先执行 S0：确认 live baseline 和 capability 口径没有漂移。
2. 再执行 S1：只复核源码与 current code，不升级 supported。
3. 执行 S2：所有 scope / blocker / nonGoal / backend classification 必须有合法 owner。
4. 执行 S3：复采集 native oracle，得到 stable shape summary 或明确 `notCollected`。
5. 执行 S4：只有 S3 stable 时才做 parity comparison；否则保留 non-parity。
6. 执行 S5：关闭不应进入 S6 的协议和持久化边界。
7. 执行 S6：按 S3-S5 结果发布 C++ implementation 或 no-code retained gate。

## 状态纪律

- S0-S6 不得预先标 `【已实现】`。
- `notCollected` 不能自动变成 `backendGap`。
- `backendGap` 必须同时有 FreeCAD authority、native observable expected 和 current cad-core mismatch。
- C6-M4 product contract 可作为 current implementation evidence，不可直接改写成 FreeCAD parity。
- 如果 native oracle 仍失败，S6 只能发布 no-code retained non-parity gate。
