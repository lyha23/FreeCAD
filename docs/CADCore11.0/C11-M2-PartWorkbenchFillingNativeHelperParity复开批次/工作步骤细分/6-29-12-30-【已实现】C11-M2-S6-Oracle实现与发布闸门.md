## 进入 S6 的合法输入

- `notCollected`: 保留为 diagnostic / historical evidence，不创建 backend gap。
- `stable_native_expected`: 可以进入 S4 comparison；若 current cad-core mismatch，进入 S6 implementation。
- `backend_gap_candidate`: 必须有 S4 写明 native expected、current output、FreeCAD source authority、test route 和禁止 shortcut。
- `nonGoal_closed`: 只能作为 release boundary，不得落代码。
- `releaseGate`: 发布 docs / capability / tests 状态。

## S6 发布结论

S6 关闭为 docs-only no-code retained non-parity release gate，`release_flag=no_code`。依据如下：

- S3 的 `C11M2-SCOPE-101/102/201/202` 均为 `notCollected_s3_reconfirmed`，没有 stable native helper `shape_summary`。
- S3 的 `C11M2-SCOPE-203` 只是 direct wrapper `dependency_retained_s3_diagnostic_control_only`，不能作为 request-local `Part.makeFilledFace` expected。
- S4 已关闭为 `diagnostic_retained_s4_no_stable_native_expected`，没有 `backend_gap_candidate`、没有 `no_gap` comparison、没有 C11-M2 expected/fixtures。
- S5 已关闭为 `nonGoal_closed_s5`，native DocumentObject、Surface Workbench GUI/native feature、mutable wrapper lifecycle、direct wrapper UV DTO、full Part surface family、adapter output repair、product contract as parity without stable oracle 和 cross-request shape state 都不能进入 S6 backend gap。
- 当前 `part_workbench.filling.status` 继续是 `supported_expected_backed_plus_c6m5_product_contract_non_parity`，`remaining_gaps=[]`，`historical_native_helper_evidence` 和 six retained narrowed helper evidence 继续保留。

因此 C11-M2 不声明 FreeCAD parity，不创建 `cad-core/fixtures/c11m2`，不改 C++、fixtures、tests、capability、collectors 或 expected。因为没有代码 / capability / fixtures 改动，本轮 code gate validation 不需要执行；`cmake --build build` 和 `python3 -m unittest tests.test_p8_features tests.test_expected_fixtures tests.test_adapters` 仅在未来 S6-like code gate 真正修改这些边界时才必跑。
