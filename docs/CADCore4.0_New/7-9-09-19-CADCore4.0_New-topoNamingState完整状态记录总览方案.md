# CADCore4.0_New topoNamingState 完整状态记录总览方案

## 结论

本方案包的目标不是继续旧 C4-M4 压力回归，而是建立一条新的 topoNamingState 完整状态记录主线：

- CAD Core 每次 recompute 后发布完整 `topoNamingState` 快照。
- 客户端只保存并原样带回该快照，不解析、不合并、不局部重放。
- CAD Core 在下一次 recompute 中校验旧 state，并只把它用于 `StableSubList` 恢复、mapper history 诊断和 `elementReferenceUpdates` 建议。
- `cad-core` runtime 发布的 state 要逐步对齐 `cad-core/fixtures/**/expected/*.freecad.json` 中 FreeCAD native expected 的字段、key、raw/canonical mapped name 和引用更新语义。

## 和旧方案的关系

本目录不作为旧 `docs/CADCore4.0` 的子包或延续包执行。旧 C4-M4 关注 ReferenceRecovery / TopoNamingPressure 的压力 fixture；本包关注完整 topoNamingState 协议状态本身。

旧方案可以作为历史背景，但不得作为本包的验收口径。本包的验收口径来自：

- `docs/接口规定/7-8-11-08-topoNamingState客户端携带状态接口方案.md`
- `cad-core/fixtures/**/expected/*.freecad.json`
- `cad-core/tools/collect_freecad_expected.py`
- FreeCAD 源码中的 `NamedShape`、`ElementMap`、`MappedName`、`TopoShapeMapper`、`PropertyLinks` 语义

## 当前基线

当前 `cad-core` 已经具备完整状态记录主线的骨架：

- response 中发布 `topoNamingState.schemaVersion`、`producer`、`documentHash`、`objects`。
- request 中的 schema / producer / documentHash / objectHash / elementMap encoding / childElementMaps encoding 已有 hard-fail 验证。
- C4M6 runtime contract 已覆盖 Body Tip child map、Compound child map、mapperHistory evidence 和 ReferenceShadow placeholder update。
- `elementMap.entries` 和 `childElementMaps[*].elementMap.entries` 的 key 已按协议使用 `mappedName.canonical`。

当前未关闭的核心缺口是 FreeCAD exact mapped-name parity：

| 场景 | 当前 cad-core | FreeCAD expected | 结论 |
| --- | --- | --- | --- |
| Body Tip child map | `Pad.Edge10;:H*,E` | `Pad.#10:1;:G;XTR;:H*:*,E` | 缺 FreeCAD ElementMap producer byte 语义 |
| Compound child map | `ChildBoxA.Edge10;:H*,E` | `Edge10;:H*,E` | child map entry key 仍带父级 source owner 前缀 |
| mapperHistory probe | ids / evidence 已对齐 | ids / evidence 已对齐 | 可作为当前已闭环基线 |
| ReferenceShadow placeholder | update 已发出 canonical StableSubList | expected canonical StableSubList | 可作为当前已闭环基线 |

## 状态模型边界

`topoNamingState` 必须记录以下内容：

- 文档级：`schemaVersion`、`producer`、`documentHash`。
- 对象级：`objectHash`、`elementMapVersion`、`subshapes`、`elementMap`、`childElementMaps`、`mapperHistory`。
- subshape 级：`rawFreecadMappedName`、`canonicalFreecadMappedName`、`resolvedIndexed`、`identityStatus`。
- element map entry：`target`、`shapeKind`、`source`、`mappedName.raw`、`mappedName.canonical`、`recoverability`、`evidence`。
- child map：`key`、`ownerObject`、`childObject`、`pathPrefix`、`elementMap`。
- mapper history：stable id、source/target endpoint、relation、maker stage、recoverability、diagnostic status。

`topoNamingState` 不得记录或承担以下内容：

- 不保存完整对象 BREP。
- 不作为 shape、bbox、volume、mesh 的建模输入。
- 不让前端解析 `mappedName.canonical` 或 `mapperHistory` 来做业务合并。
- 不在 adapter、runtime response shaping 或 executor 中靠 fixture 名、bbox、几何顺序、source index 猜 stable identity。

## 分层落点

| 层 | 责任 | 主要文件 |
| --- | --- | --- |
| `document` | 解析 `topoNamingState`、`StableSubListSource`、`ReferenceShadow`，保持 graph 是唯一建模事实 | `cad-core/src/app/property_links.cpp`、`cad-core/src/app/document.cpp` |
| `topo` / `part` | 生产 FreeCAD-style `NamedShape`、`ElementMap`、mapped-name、child map、mapper history 账本 | `cad-core/src/part/topo_shape.cpp`、`cad-core/src/topo/freecad_mapped_name_codec.cpp`、`cad-core/src/part/topo_shape_mapper.cpp` |
| `features` | 按 FreeCAD 调用链把 producer history 交给 topo 层，不拼输出 token | `cad-core/src/part_design/body.cpp`、`cad-core/src/part/part_compound.cpp`、后续 PartDesign / Part producer |
| `runtime` | 校验旧 state，发布新 state，发出 elementReferenceUpdates 和 diagnostics | `cad-core/src/runtime/topo_naming_state.cpp`、`cad-core/src/runtime/recompute.cpp`、`cad-core/src/runtime/reference_resolution.cpp` |
| `fixtures/tests` | 用 FreeCADCmd expected 锁定协议与实现差距 | `cad-core/fixtures`、`cad-core/tests/test_topo_naming_state_response.py` |

## 第一批闭环

第一批只做 C4M6，不扩大到全量 fixtures。原因：

- C4M6 覆盖完整 state 最小闭环：first recompute、Body Tip、Compound child map、mapperHistory、hard-fail、ReferenceShadow。
- 当前差距集中在 mapped-name producer byte 语义，不是几何重算缺口。
- 先用 C4M6 exact parity 防止继续用 runtime contract 测试掩盖 FreeCAD byte-level 差异。

第一批完成标准：

- `topo-state-body-tip-stable-recovery.freecad.json` 的 Body `elementMap.entries` / child map entries 与当前 `cad-core` 输出对齐。
- `topo-state-link-compound-child-maps.freecad.json` 的 Compound child map key、entry key、raw/canonical token 与当前 `cad-core` 输出对齐。
- `topo-state-mapper-history-events.freecad.json` 的 mapperHistory ids 与 entry evidence 继续保持对齐。
- `topo-state-reference-shadow-brep.freecad.json` 的 `elementReferenceUpdates` 与 canonical stable update 继续保持对齐。
