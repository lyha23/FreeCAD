# C4-M0 目标范围审计与矩阵重建方案

## 目标

C4-M0 先回答“4.0 还要复刻什么”。它不直接实现新 feature，而是把 C3.0 的冻结表、capability、oracle 队列和当前 `cad-core` 代码重新映射到仓库目标，产出可执行的 4.0 矩阵。

当前 C4-S0 审计已把根级 blocker、source、oracle、non-goal、validation 与各专题包本地 scope / blocker / package index 对齐到同一套闭环字段：source authority、cad-core landing、oracle / diagnostic、validation 和 next owner。后续 C4-M1..M6 从这些矩阵领取，不再恢复 broad `known_gap` 或 `complete_*` 占位。

## 审计维度

| 维度 | 需要输出的结论 |
| --- | --- |
| `covered_full` | 是否仍符合当前源码、fixture、capability 和 expected；若只覆盖当前语义边界，边界必须写清楚 |
| `first batch` | 是否属于仓库目标内的必补语义；若是，拆成 C4 feature-family 队列 |
| `covered_representative` | 是否只是 fallback；不得升级为完整支持 |
| diagnostic-only | 是否满足前端运行时需要；若需要成功路径，拆成 oracle-first 队列 |
| 非目标 | GUI、完整 GCS solver、Workbench、session、BREP 持久化必须继续排除 |

## 交付物

- `CADCore4.0` 总览中的阶段表保持最新。
- 新增或更新 4.0 capability matrix，字段至少包含：能力 ID、FreeCAD 源码依据、cad-core 落点、当前状态、优先级、oracle、fixture、diagnostic、remaining boundary。
- 新增 4.0 oracle queue，禁止 broad `known_gaps`。
- 每个后续细分方案都能追溯到一个矩阵项。
- 每个 root / package blocker 都能追溯到源码依据、cad-core 落点、oracle / stable diagnostic、validation 命令和 next owner。

## 初始分级

| 优先级 | 定义 | 默认阶段 |
| --- | --- | --- |
| C4-P0 | 会破坏长期引用、错误 recompute、ElementMap / MapperHistory 或跨请求前端 graph 稳定性 | C4-M0 / C4-M4 |
| C4-P1 | 前端常用 Sketch / Part / PartDesign 建模链缺失或只停留在 first batch | C4-M1 / C4-M2 / C4-M3 |
| C4-P2 | Assembly、runtime、adapter、mesh、worker 产品化能力不足 | C4-M5 |
| C4-P3 | 低频、GUI-only、Workbench-only 或不进入前端运行时目标的能力 | 只记录边界，不进入实现 |

## 非目标

- 不用 C4-M0 改 C++ 代码。
- 不把旧 C3.0 已关闭的 broad gap 恢复成新 blocker。
- 不直接把 FreeCAD 全功能清单搬成 4.0 任务。
