# CADCore4.0 总览方案

## 目标

CADCore4.0 的目标不是迁移完整 FreeCAD 产品，而是在 C3.0 冻结基线之后，把前端 CAD 运行时确实需要的 FreeCAD 几何建模核心语义继续补完整、补稳定、补可验收。

4.0 继续以本仓库 FreeCAD `src/` 为语义来源，以 `cad-core/` 为无状态几何计算核心。前端仍保存完整 `DocumentObject graph`；后端每次只根据请求 graph、目标和运行时参数重算 shape、mesh、subshape、topo naming、引用更新建议与 diagnostics。

## C3.0 基线

CADCore4.0 以当前 `docs/CADCore3.0` 冻结状态为起点：

| 领域 | C3.0 基线 |
| --- | --- |
| Document / graph / runtime | FreeCAD 风格 `DocumentObject graph`、属性链接、recompute target、diagnostics 和 request-local update channel 已成立 |
| TopoNaming / ElementMap | `MapperHistory` core、producer matrix、ElementMap policy、WireJoiner full ledger 已进入统一 history 路径，当前无笼统 `topo_history.remaining_gaps` |
| Sketcher | solver-facing diagnostics、request-local DoF、常用几何更新、ExternalGeometry Frozen / Detached / Missing 第一批和 InternalShape producer evidence 已覆盖；不代表完整 GCS solver |
| Part | Offset / Offset2D / Thickness / Section、Part surface family 第一批、conic geometry wrapper 和部分 producer history 已覆盖 |
| PartDesign | Pad / Pocket、Body chain、DressUp、Pattern、Hole、taper 和 UpToShape 多面 LinkSubList 已形成当前基线 |
| Link / Assembly | Link transaction、CopyOnChange deep copy、reference lifecycle、Assembly grounded Ondsel path 和 placement writeback 已覆盖；representative solver 仍只是 fallback |
| Adapters | CLI / C ABI / Worker / WASM / streaming mesh / binary mesh 复用同一 core recompute，adapter 不承载建模语义 |

## 4.0 范围

4.0 只接收满足以下条件的任务：

- 属于文档对象图、属性与链接、依赖分析、recompute、草图、Part / PartDesign 特征链、几何建立、拓扑命名、拓扑元素追踪、几何结果映射或前端 CAD 运行时需要的几何内核能力。
- 能从本仓库 `src/` 找到明确 FreeCAD 源码依据。
- 能落到 `cad-core` 的 `app`、`graph`、`runtime`、`sketcher`、`part`、`part_design`、`mesh`、`assembly` 或 `adapters` 清晰边界。
- 能用 native oracle、expected fixture、focused unit test、capability metadata 或稳定 diagnostic 验收。

4.0 不接收以下任务：

- FreeCAD GUI、Workbench、ViewProvider、TaskPanel、命令面板或编辑器 UI 行为。
- 完整 Sketcher GCS solver 复刻；只扩展 solver-facing 输入、状态、diagnostics、必要 geometry update 和 topo naming 相关语义。
- 跨请求后端 document session 或后端持久 shape cache。
- 除 `ReferenceShadow.brep` 单 subshape snapshot 以外的 BREP 长期状态。
- 用 fixture 名称、输出顺序、bbox、几何类型排序或 source edge 猜测修正 topo naming。

## 阶段拆分

| 阶段 | 主线 | 目标 |
| --- | --- | --- |
| C4-M0 | 目标范围审计与矩阵重建 | 把 C3.0 的 `first batch`、`covered_full`、`covered_representative` 和 explicit boundary 重新按仓库目标分级，产出 4.0 可执行队列 |
| C4-M1 | Part Workbench surface family 补完 | 从 ProjectOnSurface、RuledSurface wire/wire、Loft / Sweep profile family、Filling、GeomPlate advanced constraints 等明确边界推进 |
| C4-M2 | PartDesign feature family 补完 | 对前端常用 PartDesign Revolution / Groove / Loft / Pipe / Boolean / Datum 等做源码审计、oracle 队列和必要 executor / history 补齐 |
| C4-M3 | Sketcher 与 ExternalGeometry 扩展 | 扩展 solver-facing 关系、复杂 ExternalGeometry projection / intersection、InternalShape 与 reference recovery，不做完整 GCS solver |
| C4-M4 | 引用恢复与 topo naming 压力回归 | 针对长期编辑、rename、Link retag、import change、ShapeFix / Refine / Boolean / DressUp / transformed 混合链补压力 fixture 和 update contract |
| C4-M5 | Assembly / runtime / adapter 产品化补齐 | 扩展目标内 JointType / solver validation / writeback lifecycle，并加固 Worker / WASM / mesh / binary contract |
| C4-M6 | 4.0 冻结收口 | 同步 capabilities、oracle fixture 队列、expected、diagnostics、文档和阶段回归，形成 4.0 freeze |

## 推进规则

- 每个阶段先读 FreeCAD 源码，记录调用链，再写 cad-core 落点和 fixture 草案。
- 每个实现批次必须是最小完整语义批次，不能只挑单个易过 fixture。
- 每个新增 capability 必须同步 `cad-core/src/adapters/c_api/c_api.cpp`、focused tests、docs 和 remaining boundary。
- `known_gap` 只能作为明确 diagnostic 或后续队列，不能恢复成 broad `complete_*` 占位。
- 完成实现并验证后，方案文档按仓库规则加 `【已实现】`，保留原时间前缀。
