## 范围修正

之前的 `full Part surface family` 只在 PARTCONIC 与 RuledProjection 第一批里作为 package-local non-goal 出现；从本总览开始，它升级为 cad-core 后端必迁主线。也就是说：

- `C3M4-PartWorkbenchSurface-RuledProjection收口主线` 仍然是第一条 surface 主线，负责 `Part::RuledSurface` 和 `Part::ProjectOnSurface` 裁决。
- `Loft`、`Sweep`、`Filling`、`PipeShell`、`GeomPlate` 不再是长期非目标，而是拆成独立收口包。
- 每个包都必须走 FreeCAD source authority、cad-core executor/helper、oracle fixture、focused tests、capability publication 的闭环。

## 必迁后端主线分组

已基本收口的能力仍按 `docs/CADCore3.0/capabilities-gap对照表.md` 保持：Document graph、Link lifecycle、TopoHistory / ElementMap / MapperHistory、Sketcher solver-facing diagnostics、Part offset / thickness / section、PartDesign body / Pad / Pocket / Hole、Assembly core solver、adapter productization。

剩余必须收口内容分成六个 Part surface 包：

1. `C3M4-PartWorkbenchSurface-RuledProjection收口主线`
   - 已存在。
   - 第一批：`Part::RuledSurface` edge/edge。
   - 第二裁决：`Part::ProjectOnSurface` 窄批或独立后续。
2. `C3M4-PartWorkbenchSurface-Loft收口主线`
   - `Part::Loft` source-backed executor。
   - `TopoShape::makeElementLoft()` / `BRepOffsetAPI_ThruSections` / `MapperThruSections`。
3. `C3M4-PartWorkbenchSurface-SweepPipeShell收口主线`
   - `Part::Sweep` source-backed executor。
   - `TopoShape::makeElementPipeShell()` / `BRepOffsetAPI_MakePipeShell`。
   - 覆盖 low-level PipeShell 后端能力，不只覆盖 Sweep GUI 属性。
4. `C3M4-PartWorkbenchSurface-Filling收口主线`
   - `Part.makeFilledFace()` / `TopoShape::makeElementFilledFace()`。
   - `BRepFill_Filling` 参数、boundary/support/order、face output 和 maker history。
5. `C3M4-PartWorkbenchSurface-GeomPlate收口主线`
   - `Part.GeomPlate` Python/geometry wrapper 后端能力。
   - `Tools::makeSurface()`、`GeomPlate_BuildPlateSurface`、CurveConstraint / PointConstraint、PlateSurface。
   - 不伪造不存在的 DocumentObject；按 geometry DTO / helper / oracle 路径发布。
6. `C3M4-PartWorkbenchSurface-Family冻结收口主线`
   - 统一更新 CADCore3.0 capability、oracle fixture 队列、adapter metadata 和 docs。
   - 明确哪些是 supported、diagnostic boundary、package-local non-goal。

## 完成定义

一个 surface 包只有同时满足以下条件才算收口：

- FreeCAD source authority 已记录到矩阵，且包含源码文件、类/函数、关键字段或短句。
- cad-core 落点清楚，不能把高层语义塞进 adapter 或 fixture 特例。
- 至少有一组成功 fixture 和一组失败/diagnostic fixture。
- 成功 fixture 有 FreeCAD expected，且 focused tests 通过。
- TopoNaming / ElementMap / maker history 如有 FreeCAD 依据，必须有输出字段或 diagnostics 约束。
- CADCore3.0 capability 文档和 C API metadata 只发布已验证范围。
- `工作步骤细分` 对应文件改名为 `【已实现】`。

## 进度口径

如果继续把 full Part surface family 算入 cad-core 必迁后端主线，当前完成度不应再按 80-85% 估。更保守的口径是：

- 已完成：约 70-75%。
- 剩余：约 25-30%。
- 剩余大头集中在 Part surface family，而不是 Document / Link / TopoNaming / PartDesign / Assembly 基础主线。

## 执行顺序

建议顺序固定为：

1. RuledProjection：先完成 `Part::RuledSurface`，再裁决 `ProjectOnSurface`。
2. Loft：复用已有 `BRepOffsetAPI_ThruSections` 和 taper history 基础。
3. SweepPipeShell：复用 Hole ModelThread 已用过的 PipeShell 低层能力，但按 Part::Sweep / PipeShell source-backed 重新收口。
4. Filling：补 `BRepFill_Filling` face surface 构造与 history。
5. GeomPlate：补 geometry wrapper / plate surface 后端能力。
6. Family冻结：统一 capability / oracle / adapter / docs。
