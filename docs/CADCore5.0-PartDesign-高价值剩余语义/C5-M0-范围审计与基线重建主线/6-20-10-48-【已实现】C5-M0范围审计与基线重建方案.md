# 【已实现】C5-M0 范围审计与基线重建方案

## 目标

C5-M0 只做范围和执行基线，不做代码实现。目标是把 C4 freeze 的 PartDesign remaining boundary 转成可执行的 C5 专题包，并确保每个包都有 source authority、cad-core 落点、oracle / diagnostic 路径和验收命令。

## 范围

- 输入基线：`docs/CADCore4.0/C4-M6-Freeze收口主线/6-20-05-24-【已实现】C4-M6-freeze收口总结.md`。
- PartDesign 依据：`src/Mod/PartDesign/App/FeatureRevolution.cpp`、`FeatureGroove.cpp`、`FeatureRevolved.cpp`、`FeatureBoolean.cpp`、`FeatureLoft.cpp`、`FeaturePipe.cpp`、`Datum*.cpp`、`Body.cpp`。
- 共享依据：`src/Mod/Part/App/TopoShapeExpansion.cpp`、`AttachExtension.cpp`、`Attacher.cpp`、`src/App/PropertyLinks.cpp`。
- 输出：全局矩阵和每个专题包的 package-local scope / blocker 队列。

## 产出

| 项 | 内容 |
| --- | --- |
| source candidates | C5 只认具体 FreeCAD source chain，不接受 broad PartDesign gap |
| scope review matrix | 每个阶段对应一个 owner 和验收边界 |
| fixture / oracle matrix | 每个 supported row 必须有 native expected 或稳定 diagnostic |
| non-goal registry | GUI、完整 Workbench、adapter-side logic、LinkStage3-only Type 等边界显式记录 |
| blocker queue | 后续子 agent 只从 pending blocker 领取任务 |

## S0 审计结果

- 全局矩阵补齐 `C5-ORC-203` Boolean stable diagnostics 与 `C5-ORC-303` Loft/Pipe sewing MapperHistory，消除 scope 引用但 oracle 矩阵缺行的问题。
- `C5-BLK-001`、`C5M0-BLK-001`、`C5M0-BLK-002` 已关闭为矩阵重建 / 队列校验完成；M1-M5 继续保留各自 pending worker。
- C5-M3 原本的 broad Loft / Pipe local blocker 已拆成 Loft source、Loft oracle、Pipe source、Pipe oracle 和 shared sewing topo blocker，避免后续 worker 用一个大任务覆盖多条 FreeCAD 调用链。
- GUI、完整 Workbench、跨请求 session、adapter-side modeling、bbox / output-order / fixture-name topo correction 等 non-goal 边界继续由全局 non-goal registry 保持。
